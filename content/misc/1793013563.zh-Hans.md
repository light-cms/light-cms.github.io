Cloudflare网页、Vercel和Netlify都可以主办现代的网络项目，但它们适合不同类型的工作。对于一个主要是静态站点来说，Cloudflare页面常常是很好的价值。对于一个带有服务器渲染的下一步.js重型应用，Vercel通常是最简单的。对于一个想要在一个地方部署预览、函数和内置工具的 Jamstack 站点，Netlify 常常是一个很好的中间选择。

## 从您需要的内容开始

在您比较功能之前，知道您打算上网的内容。

| 项目类型                 | 好的默认   | 为什么原因                 |
| -------------------- | ------ | --------------------- |
| 博客，文档，登陆页面           | 云端页面   | 使用简单的 HTML 文件设置快速静态主机 |
| 下次.js/服务器渲染的应用       | Vercel | 关闭框架连接和轻松预览           |
| 带有表单/函数的 Jamstack 站点 | 网络化    | Git 部署内置工具            |

## 云端页面

Cloudflare页面在静态站点和前端使用单独的后端时很有效。它靠近Cloudflare的边缘网络，如果您稍后需要它，它可以链接到其他服务。

主要的权衡是代码运行的地方。如果你移动代码到工人，它不会在标准的 Node.js 服务器设置中运行。这适用于许多边缘任务，但你可能需要更改你的代码。

## Vercel

当您的应用需要框架功能，特别是服务器渲染、预览部署和图像优化时，Vercel是一个很好的选择。对于Next.js团队来说，通常很容易从Git推送到预览，然后再制作。

折衷是成本和适宜的。不要仅仅因为项目受欢迎而选择Vercel ；看看项目是否需要服务器渲染的功能。在您发送实时流量之前检查定价计划。

## 网络化

Netlify对静态和Jambstack项目很好，这些项目需要Git工作流程和内置工具，如部署预览和服务器功能。多年来，它一直在这样做，这么多的前沿小组了解工作流程。

## 简单的决策检查

使用这三个问题：

1. 这主要是静态吗？开始使用 Cloudflare 页面。
2. 它是否需要服务器渲染或关闭 Next.js 层？请考虑Vercel。
3. 您想要使用内置工具的静态主机吗？试试网络.

在您选择之前，请检查每个主机的当前计划限制、商业使用规则、带宽成本以及其官方定价页面和文档中的运行时间限制。主机详细信息可以更改，所以确认主机自己的文档中的每个限制，而不是依赖内存。
