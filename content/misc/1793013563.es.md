Cloudflare Pages, Vercel, y Netlify pueden albergar proyectos web modernos, pero se ajustan a diferentes tipos de trabajo. Para un sitio en su mayoría estático, Cloudflare Pages es a menudo un buen valor. Para una aplicación Next.js-heavy con renderizado de servidores, Vercel es generalmente el más fácil. Para un sitio web de Jamstack que quiere desplegar previsualizaciones, funciones y herramientas integradas en un solo lugar, Netlify suele ser una buena elección intermedia.

## Comience con lo que necesita

Antes de comparar características, sepa lo que planea poner en línea.

| Tipo de proyecto                                | Bueno por defecto     | Por qué                                                                   |
| ----------------------------------------------- | --------------------- | ------------------------------------------------------------------------- |
| Blog, docs, página de destino                   | Páginas de Cloudflare | Alojamiento estático rápido con una simple configuración de archivos HTML |
| Aplicación renderizada por servidor             | Vércel                | Cerrar lazos de framework y previsualizaciones fáciles                    |
| Sitio web de Jamstack con formularios/funciones | Red                   | Herramientas integradas para desplegar Git                                |

## Páginas de Cloudflare

Cloudflare Pages funciona bien para sitios estáticos y frontends que usan un backend separado. Está cerca de la red de vanguardia de Cloudflare y puede conectarse a sus otros servicios si los necesita más tarde.

La compensación principal es donde se ejecuta el código. Si se mueve el cambio de código a Workers, no se ejecuta en una configuración estándar del servidor Node.js. Esto funciona para muchas tareas de borde, pero puede que necesites cambiar tu código.

## Vércel

Vercel es una buena elección cuando su aplicación necesita características de framework, especialmente renderizado de servidores, previsualizaciones y optimización de imágenes. Para los equipos Next.js, normalmente es fácil pasar de un empuje de Git a una vista previa y luego a la producción.

La compensación es costosa y adecuada. No escoja Vercel sólo porque sea popular; compruebe si su proyecto necesita características representadas por el servidor. Compruebe el plan de precios antes de enviar tráfico en vivo.

## Red

Netlify funciona bien para proyectos estáticos y Jamstack que necesitan un flujo de trabajo Git y herramientas integradas como la implementación de previsualizaciones y funciones sin servidor. Ha hecho esto durante años, así que muchos equipos de frontend conocen el flujo de trabajo.

## Una simple comprobación de decisión

Utilice estas tres preguntas:

1. ¿Es estático en su mayoría? Comenzar con Cloudflare Pages.
2. ¿Necesita renderizar el servidor o cerrar los empates de Next.js? Consideremos a Vercel.
3. ¿Quiere un alojamiento estático con las herramientas integradas? Prueba Netlify.

Antes de elegir, compruebe los límites actuales del plan de cada host, las reglas de uso de la empresa, los costos de ancho de banda y los límites de tiempo de ejecución en sus páginas oficiales de precios y documentos. Los detalles de alojamiento pueden cambiar, así que confirme cada límite en los documentos propios del huésped en lugar de depender de la memoria.
