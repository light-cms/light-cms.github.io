Cloudflare Pages, Vercel, et Netlify peuvent tous héberger des projets web modernes, mais ils correspondent à différents types de travail. Pour un site statique pour la plupart, Cloudflare Pages est souvent une bonne valeur. Pour une application Next.js-heavy avec le rendu du serveur, Vercel est généralement le plus facile à utiliser. Pour un site Jamstack qui veut déployer des aperçus, des fonctions et des outils intégrés en un seul endroit, Netlify est souvent un bon choix.

## Commencez par ce dont vous avez besoin

Avant de comparer les fonctionnalités, sachez ce que vous prévoyez de mettre en ligne.

| Type de projet                              | Bon par défaut                        | Pourquoi                                                                  |
| ------------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------- |
| Blog, doc, page d'accueil                   | Pages de la fusée éclairante nuageuse | Hébergement statique rapide avec une configuration de fichier HTML simple |
| Suivant.js/application rendu par le serveur | Collier                               | Fermer les liens du framework et faciliter les aperçus                    |
| Site de jamstack avec formes/fonctions      | Netlify                               | Outils intégrés pour les déploiements Git                                 |

## Pages de la fusée éclairante nuageuse

Les pages de Cloudflare fonctionnent bien pour les sites statiques et les interfaces qui utilisent un backend séparé. Il est proche du réseau de bord de Cloudflare et peut se connecter à ses autres services si vous en avez besoin plus tard.

Le compromis principal est l'endroit où le code s'exécute. Si vous déplacez le code vers Workers, il ne s'exécute pas dans une configuration standard du serveur Node.js. Cela fonctionne pour de nombreuses tâches de bord, mais vous devrez peut-être modifier votre code.

## Collier

Vercel est un bon choix lorsque votre application a besoin de fonctionnalités de cadre, en particulier le rendu du serveur, les déploiements de prévisualisation et l'optimisation de l'image. Pour les équipes de Next.js, il est généralement facile de passer d'un Git push à un aperçu puis à une production.

Le compromis est le coût et l'adaptation. Ne choisissez pas Vercel simplement parce qu’il est populaire ; vérifiez si votre projet a besoin de fonctionnalités affichées par le serveur. Consultez le plan tarifaire avant d'envoyer le trafic en direct.

## Netlify

Netlify fonctionne bien pour les projets statiques et Jamstack qui ont besoin d'un flux de travail Git et d'outils intégrés comme le déploiement d'aperçus et de fonctions sans serveur. Il l'a fait depuis des années, tant d'équipes en frontend connaissent le flux de travail.

## Un simple contrôle de décision

Utilisez ces trois questions :

1. Est-ce surtout statique ? Commencez avec Cloudflare Pages.
2. Est-il nécessaire de rendre le serveur ou de fermer Next.js ? Prenons Vercel.
3. Voulez-vous un hébergement statique avec des outils intégrés ? Essayez Netlify.

Avant de choisir, vérifiez les limites actuelles des forfaits de chaque hôte, les règles d’utilisation de l’entreprise, les coûts de bande passante et les limites de temps d’exécution dans ses pages de tarification et ses documents officiels. Les détails d'hébergement peuvent changer, donc confirmez chaque limite dans les propres docs de l'hôte au lieu de vous fier à la mémoire.
