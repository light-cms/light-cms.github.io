Tanto o LightCMS como Páginas CMS armazenam seu conteúdo como arquivos no Git, assim você nunca perderá a propriedade do repositório. A divisão real é naquilo que você gasta a maior parte da sua edição do tempo: artigos longos de Markdown ou campos na frente estruturados.

Páginas CMS coloca os campos de formulário e esquemas de coleta primeiro, enquanto o LightCMS coloca um editor de documento visual primeiro.

## Como os modelos de edição comparam


| área                      | CMS                                                                     | CMS das Páginas                                                     |
|:------------------------- |:----------------------------------------------------------------------- |:------------------------------------------------------------------- |
| Interface primária        | Dica: Toque no editor de Markdown visual                                | Editor de formulários orientados por configuração                   |
| Melhor ajuste             | Artigos, documentos e redações de longa forma                           | Registros estruturados, catálogos e registros pesados de metadados  |
| Armazenamento de conteúdo | Markdown com questão frontal no GitHub                                  | Arquivos e mídia no GitHub                                          |
| Configuração              | Conexão do aplicativo GitHub (PostgreSQL necessário se auto-hospedado)  | Arquivo de configuração do repositório que define coleções e campos |
| Workflow de escrita       | Rascunhos, formatação, colar imagem, desenhar IA e impor ditado por voz | Validação de campos, seleções, datas e entradas de texto rico       |


Esta diferença aparece no momento em que você abrir um post: LightCMS é como uma mesa de escrita, Enquanto Páginas CMS se parece com um formulário de administrador sobre o repositório.

## Quando o CMS for a melhor escolha

Páginas CMS faz mais sentido quando seu site é construído em torno de registros estruturados, em vez de em formato longo. Se mantiver diretórios, changelogs, listagens de produtos ou páginas onde datas personalizadas, seleções, booleanos e os campos de primeira matéria aninhados importam, definindo esses esquemas em um arquivo de configuração mantém os editores de quebrar sua construção.

Também é mais fácil de adotar se você não quiser executar a base de dados de aplicações para o próprio CMS.

## Quando o CMS é a melhor escolha

LightCMS se encaixa melhor quando a tarefa principal é escrever e editar artigos. Se você ou seus escritores passam a maior parte do dia redigindo 1.000 posts com títulos, códigos, mesas, e imagens em linha, um editor de documentos baseado no navegador sai mais rápido do que uma pilha de entradas de formulário.

Antes de escolher qualquer ferramenta, teste tanto o layout atual do repositório, como as convenções da primeira matéria e da pasta de imagem.
