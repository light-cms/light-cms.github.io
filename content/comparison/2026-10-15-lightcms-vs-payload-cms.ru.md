LightCMS и Payload CMS решают различные проблемы. LightCMS — редактор на основе Git для статического контента сайта, хранимого как Markdown в репозитории. Payload CMS это бесконечная CMS которая хранит контент в базе данных и раскрывает его через API приложений и администрируемый интерфейс.

## Сравнение архитектуры

| Область               | LightCMS                                 | Нагрузка CMS                                                    |
| :-------------------- | :--------------------------------------- | :-------------------------------------------------------------- |
| Хранилище содержимого | Markdown/файлы в Git                     | Сохраненные базы данных записи                                  |
| Модель доставки       | Статическая сборка сайта + CDN           | Отправка приложений с помощью API / безголовной сети            |
| Требуется Runtime     | Собрать конвейер и статический хост      | Сервер и база данных приложений                                 |
| Лучший подбор         | Блоги, документация, маркетинговые сайты | Приложения/товары, нуждающиеся в структурированных API контента |
| Versioning            | Git history                              | Функции версий CMS/базы данных                                  |

## Выбор между ними

Payload имеет смысл, когда контент структурирован, взаимоотношений или должен использоваться более чем одним приложением. Если вам нужны API, пользовательские модели контента, основанные на ролях рабочих процессов или поставки приложений, то для этого построена система Payload.

LightCMS имеет смысл, когда конечным результатом является статичный сайт, и ваш контент работает и с файлами Markdown. Если история Git, портативность и простое дело больше всего, то статический маршрут проще жить.

Реальный вопрос заключается в том, что вы строите. Если вам нужна платформа для контента внутри приложения, то ее ценят дополнительные подвижные части Payload. Если вы публикуете сайт, они обычно не являются. Смотрите [LightCMS против контента](/comparison/lightcms-vs-contentful) или [Headless CMS Explained](/blog/headless-cms-explained/) для сравнения.
