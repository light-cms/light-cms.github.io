LightCMS和内容丰富的对象是不同的使用案例。 LightCMS is designed for Git based static site publishing, where content lives in a repository and is deployed as static files. 内容丰富的是无主的 CMS 通过网站、应用和其他频道的 API 传输结构化内容。

## 比较

| 区域   | LightCMS                       | 有内容           |
| :--- | :----------------------------- | :------------ |
| 主要模式 | Git based CMS for static sites | 无头CMS         |
| 内容存储 | 仓库标记/文件                        | 供应商管理的内容平台    |
| 发货   | 静态构建输出                         | 内容 API        |
| 最合适的 | 博客、文档、营销网站                     | 多频道企业内容操作     |
| 治理   | Git 工作流、PR、repo 权限             | 角色、工作流、环境、本地化 |
| 成本模式 | 产品/自托管成本变化                     | 订阅/使用/基于座位的价格 |

## 二者之间的选择

当相同的内容必须跨越多个渠道并且你需要企业管理时，内容是有意义的。 Workflow 或 API 和SLA的管理平台。

当你的主输出是静态站点并且你想要生活在Git中的内容时，LightCMS就更有意义。您获得了一个简单的发布设置，但您没有得到相同的企业内容操作层。

它的规模和形成。如果您在团队、产品和渠道中运行内容，内容丰富可以证明其成本和供应商锁定是合理的。如果您正在发布一个站点，仓库拥有的Markdown 通常会更加冷静和更加便宜地运行。查看[LightCMS vs Sanity](/comparison/lightcms-vs-sanity)或[无头CMS Explained](/blog/headless-cms-explained/)。
