LightCMS y Contenidos apuntan a diferentes casos de uso. LightCMS está diseñado para la publicación de sitios estáticos basados en Git, donde el contenido vive en un repositorio y se implementa como archivos estáticos. Contentful es un CMS sin cabeza empresarial que entrega contenido estructurado a través de APIs para sitios web, aplicaciones y otros canales.

## Comparación

| Área                        | LightCMS                                      | Contenidos                                         |
| :-------------------------- | :-------------------------------------------- | :------------------------------------------------- |
| Modelo primario             | CMS basado en Git para sitios estáticos       | CMS sin cabeza SaaS                                |
| Almacenamiento de contenido | Markdown/Archivos del repositorio             | Plataforma de contenido administrada por proveedor |
| Entrega                     | Salida de construcción estática               | API de contenido                                   |
| Mejor ajuste                | Blogs, docs, sitios de marketing              | Operaciones de contenido empresarial multicanal    |
| Gobernanza                  | Flujos de trabajo Git, PRs, permisos de repo  | Roles, flujos de trabajo, entornos, localización   |
| Modelo de costo             | Los costes de producto/autosuficiencia varían | Precio basado en la suscripción/uso/asiento        |

## Eligiendo entre ellos

El contenido tiene sentido cuando el mismo contenido tiene que viajar a través de múltiples canales y se necesita un gobierno empresarial, , o una plataforma administrada con APIs y SLAs.

LightCMS tiene más sentido cuando su salida principal es un sitio estático y desea que el contenido viva en Git. Obtienes una configuración de publicación más sencilla, pero no tienes la misma capa de operaciones de contenido empresarial.

Se reduce a la escala y a la forma. Si está corriendo contenido entre equipos, productos y canales, el contenido puede justificar su costo y bloqueo de proveedores. Si está publicando un sitio, Markdown es generalmente más barato y más barato de operar.
