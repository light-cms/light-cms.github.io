Páginas CMS é um CMS baseado em Git focado na edição simples baseado em formulário sobre o conteúdo do repositório. As equipes procuram por alternativas quando precisam de interfaces de escrita mais ricas, edição visual, esquemas mais fortes, suporte a Git multi-provedores ou hospedagem gerenciada.

## Alternativas de imediato

| Alternativo    | Melhor ajuste                                                              | Troca de chave                                                    |
| :------------- | :------------------------------------------------------------------------- | :---------------------------------------------------------------- |
| CMS            | Edição Visual Markdown para sites estáticos                                | Verificar as características atuais e opções de hospedagem        |
| Decapitar CMS  | Estabelecido Git baseado em CMS com coleções orientadas pela configuração  | O fluxo de trabalho UI/config pode se sentir datado de escritores |
| TinaCMS        | Edição visual ou estruturada com sincronização do Git                      | Requer esquema / decisões de configuração                         |
| Keystatica     | Programas de conteúdo de primeira localidade orientados pelo desenvolvedor | Menos focado no escritor da caixa                                 |
| Sveltia CMS    | CMS UI baseado no navegador leve                                           | Projeto mais jovem; verifique a maturidade                        |
| Canhão Nublado | Edição visual gerenciada para equipes/agências                             | Preços comerciais                                                 |

## Critério de seleção

Quando comparando alternativas de páginas CMS, avalie:

- Experiência de edição: Campos de formulário, edição WYSIWYG ou na página.
- Suporte ao provedor Git: GitHub ou também GitLab/Bitbucket.
- Modelo de conteúdo: Elemento/formulários, esquemas digitados ou blocos estruturados.
- Manipulação de mídia: Uploads, caminhos de ativos e armazenamento externo.
- Modelo operacional: SaaS hospedado, aplicativo auto-hospedado, ou interface de administrador estático.

Para equipes que já estão usando Markdown no Git, a migração geralmente é possível sem mover conteúdo. O trabalho principal é mapeamento de campos, caminhos de mídia e fluxo de trabalho editorial.
