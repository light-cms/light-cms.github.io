Decap CMS(原为 Netlify CMS) 仍然是基于 Git 的 CMS 选项。 但当团队需要不同的编辑经验、更简单的设置、视觉编辑或特定的工作流程特性时，往往评估替代品。下面的替代品保留了Git中的内容，但在接口、主机型号和操作复杂性方面有所不同。

## 1. 一眼中的替代物

| 备选办法        | 最合适的              | 主机模型       | 折叠式...             |
| :---------- | :---------------- | :--------- | :----------------- |
| LightCMS    | 静态站点的视觉Markdown编辑 | 自托管或托管产品选项 | 比旧的 CMS 工具更小的生态系统  |
| 页面CMS       | 基于 GitHub 的简易表单编辑 | 托管或自主机     | 不适合长式WYSIWYG 写入    |
| TinaCMS     | 视觉/页面上编辑工作流       | 托管和/或自托管选项 | 安装程序和架构模型可以更多地参与   |
| 静态键         | 已输入，本地第一个内容方案     | 自主办/本地优先   | 更多面向开发者            |
| Sveltia CMS | 基于轻量浏览器的编辑        | 静态/管理界面部署  | 较小的项目; 验证功能平等      |
| GitCMS      | 经认证的审评工作流程        | 产品/服务      | 价格和治理模式不同于开放源码软件工具 |

## 如何选择

基于您的内容工作流而不是功能计数选择：

- 作者需要一个视觉编辑器：评估 LightCMS 或 TinaCMS。
- 开发者需要schema控制：评估关键静态或Decap CMS。
- 团队需要最小化的设置：计算 Pages CMS 或 Sweltia CMS 。
- AI生成的更改需要审查：评价 GitCMS。

迁移前，确认前事项兼容性、媒体路径、身份验证模型和构建管道行为。基于 Git 的 CMS 迁移是配置更改，但字段名称和媒体处理常常需要调整。

关于相关的比较，请参阅[LightCMS vs Decap CMS](/comparison/lightcms-vs-decap-cms)和[基于 Git 的顶级CMS 平台](/comparison/top-git-cms)。
