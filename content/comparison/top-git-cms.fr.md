Les outils CMS basés sur Git vous permettent de modifier le contenu dans un navigateur tout en conservant le contenu réel dans un dépôt Git. Cela vous donne un historique de version, des demandes de fusion et des fichiers simples que vous pouvez déplacer plus tard. La partie difficile est d’en choisir une, parce qu’ils promettent tous un « montage facile » et signifient des choses très différentes.

Certains sont basés sur des formulaires, d'autres sont édités sur la page, d'autres sont construits pour les développeurs, et d'autres essaient de rendre l'écriture confortable pour des personnes non techniques. Le bon choix dépend de la publication et de la structure de votre contenu.

## Comparaison rapide

| CMS               | Meilleur pour                                    | Édition du style                                   | Choses à vérifier                                                        |
| ----------------- | ------------------------------------------------ | -------------------------------------------------- | ------------------------------------------------------------------------ |
| Déclencher le CMS | Collections configurées et workflows Git établis | Interface d'administration basée sur le formulaire | Maintenance en cours, Fournisseurs Git, Configuration d'authentification |
| TinaCMS           | Édition visuelle/contextuelle                    | Édition sur page ou structurée                     | Prix actuels, auto-hébergement, workflow du schéma                       |
| Clés statiques    | Schémas définis par le développeur               | Formulaires générés à partir du code               | Prise en charge actuelle du cadre, modes cloud/local                     |
| Pages CMS         | Édition simple de GitHub                         | Tableau de bord basé sur le formulaire             | Support du fournisseur Git actuel, licence                               |
| Sveltia CMS       | Édition légère du navigateur                     | Interface d'administration sur Git                 | Parité et maturité de la caractéristique actuelle                        |
| Canon nuageux     | Sites gérés par l'Agence / le client             | Flux de travail visuels/éditoriaux                 | Tarif actuel et modèle d'hébergement                                     |
| LightCMS          | Écrivains publiant le contenu statique du site   | Éditeur de document                                | Fonctionnalités actuelles, hébergement, support du fournisseur Git       |

## Comment choisir

Commencez avec l'éditeur et non avec la liste des fonctionnalités. Si des écrivains publient des articles de forme longue, un éditeur de document se sent généralement mieux qu'un formulaire avec une zone de texte Markdown. Si votre contenu est structuré des enregistrements, des formulaires et des schémas sont mieux adaptés.

Ensuite, vérifiez le flux de travail du référentiel. Confirmez où vont les images, comment la matière première est gérée, quels fournisseurs Git sont pris en charge et si l'outil correspond à votre générateur de site statique. Un CMS qui a l'air beau dans une démo peut toujours être ennuyeux s'il écrit une première question que vos modèles ne s'attendent pas.

Enfin, soyez honnête sur les opérations. Un outil auto-hébergé vous donne le contrôle, mais vous possédez des configurations et des mises à jour. Un outil hébergé réduit la maintenance, mais vous devez être à l'aise avec les prix et la dépendance du fournisseur.

## Où LightCMS s'adapte

LightCMS est destiné aux personnes qui veulent écrire dans un navigateur et qui gardent toujours le flux de travail basé sur Git. Il s'adapte bien lorsque le travail principal est de publier des articles, des documents ou du contenu marketing sur un site statique. Ce n’est pas le cas lorsque vous avez besoin d’une API de contenu basé sur une base de données, de modèles de contenu relationnel complexes ou d’une gouvernance d’entreprise lourde.

Si vous comparez des options, ne vous arrêtez pas aux matrices de fonctionnalités. Essayez la même tâche réelle dans chaque outil : écrivez un post, ajoutez une image, éditez la première question, publiez et confirmez les constructions du site. Cela vous indique rapidement laquelle correspond à votre équipe. Voir [Git based CMS vs Traditional CMS](/blog/git-cms-vs-traditional-cms/) et [Getting Started with LightCMS](/getting-started/).
