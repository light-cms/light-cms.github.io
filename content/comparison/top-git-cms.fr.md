Git based CMS tools let you edit content in a browser while keeping the actual content in a Git repository. Cela vous donne un historique de version, des demandes de fusion et des fichiers simples que vous pouvez déplacer plus tard. La partie difficile est d’en choisir une, parce qu’ils promettent tous un « montage facile » et signifient des choses très différentes.

Some are form-based, some edit on the page, some are built for developers, and some are trying to make writing comfortable for nontechnical people. Le bon choix dépend de la publication et de la structure de votre contenu.

## Comparaison rapide

| CMS               | Meilleur pour                                    | Édition du style                                   | Choses à vérifier                                                        |
| ----------------- | ------------------------------------------------ | -------------------------------------------------- | ------------------------------------------------------------------------ |
| Déclencher le CMS | Collections configurées et workflows Git établis | Interface d'administration basée sur le formulaire | Maintenance en cours, Fournisseurs Git, Configuration d'authentification |
| TinaCMS           | Édition visuelle/contextuelle                    | Édition sur page ou structurée                     | Prix actuels, auto-hébergement, workflow du schéma                       |
| Clés statiques    | Schémas définis par le développeur               | Formulaires générés à partir du code               | Prise en charge actuelle du cadre, modes cloud/local                     |
| Pages CMS         | Édition simple de GitHub                         | Tableau de bord basé sur le formulaire             | Support du fournisseur Git actuel, licence                               |
| Sveltia CMS       | Édition légère du navigateur                     | Interface d'administration sur Git                 | Parité et maturité de la caractéristique actuelle                        |
| Canon nuageux     | Sites gérés par l'Agence / le client             | Flux de travail visuels/éditoriaux                 | Tarif actuel et modèle d'hébergement                                     |
| LightCMS          | Écrivains publiant le contenu statique du site   | Éditeur de document                                | Fonctionnalités actuelles, hébergement, support du fournisseur Git       |

## Comment choisir

Commencez avec l'éditeur et non avec la liste des fonctionnalités. If writers are publishing long-form articles, a document editor usually feels better than a form with a Markdown text area. Si votre contenu est structuré des enregistrements, des formulaires et des schémas sont mieux adaptés.

Ensuite, vérifiez le flux de travail du référentiel. Confirmez où vont les images, comment la matière première est gérée, quels fournisseurs Git sont pris en charge et si l'outil correspond à votre générateur de site statique. Un CMS qui a l'air beau dans une démo peut toujours être ennuyeux s'il écrit une première question que vos modèles ne s'attendent pas.

Enfin, soyez honnête sur les opérations. Un outil auto-hébergé vous donne le contrôle, mais vous possédez des configurations et des mises à jour. Un outil hébergé réduit la maintenance, mais vous devez être à l'aise avec les prix et la dépendance du fournisseur.

## Où LightCMS s'adapte

LightCMS is for people who want to write in a browser and still keep the Git based workflow. Il s'adapte bien lorsque le travail principal est de publier des articles, des documents ou du contenu marketing sur un site statique. It’s not the right fit when you need a database based content API, complex relational content models, or heavy enterprise governance.

Si vous comparez des options, ne vous arrêtez pas aux matrices de fonctionnalités. Essayez la même tâche réelle dans chaque outil : écrivez un post, ajoutez une image, éditez la première question, publiez et confirmez les constructions du site. Cela vous indique rapidement laquelle correspond à votre équipe. See [Git based CMS vs Traditional CMS](/blog/git-cms-vs-traditional-cms/) and [Getting Started with LightCMS](/getting-started/).
