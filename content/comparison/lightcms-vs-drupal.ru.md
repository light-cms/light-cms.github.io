[Drupal](https://www.drupal.org) - серьезный конец управления контентом с открытым исходным кодом: PHP фреймворк с моделью контента, Разрешения, мнения и экосистемы, построенные для университетов, правительств и крупных организаций с требованиями к реальному управлению.

Сравнение с LightCMS почти нечестно: они сидят на противоположных концах сложного спектра. Сравнение по-прежнему полезно, потому что много команд спрашивают, нужны ли им вес Drupal для публикации сайта.

---

## Что за каждый

**Drupal** представляет собой фреймворк приложения с CMS внутри него: сущности, поля, таксономии, роли, модули и уровень темы, работающие на PHP с базой данных SQL. Она может моделировать практически все и просит значительного опыта в возвращении.

**LightCMS** является редактором содержимого перед хранилищем: Markdown файлы с передней частью, визуальный редактор и статическая сборка. Он моделирует документы и ничего другого.

|                              | LightCMS                     | Крупал                                               |
| :--------------------------- | :--------------------------- | :--------------------------------------------------- |
| **Стек**                     | Файлы + SSG + CDN            | PHP + SQL база данных                                |
| **Модель контента**          | Передние поля                | Сущности, поля, комплекты                            |
| **Разрешения**               | Доступ к репозиторию         | Права доступа к ролям/полям                          |
| **Рендеринг**                | Статическая статика          | Сервер, кэшируемый                                   |
| **Темы**                     | Шаблоны SSG                  | Drupal темы + предпроцесс                            |
| **Техническое обслуживание** | Только изменения содержимого | Ядро/модуль обновления, рекомендации по безопасности |
| **Навык для работы**         | Браузер для писателей        | Разработчики почти для всех                          |
| **Стоимость**                | Хостинг                      | Хостинг + время разработчика                         |

## Где Drupal побеждает

- **Сложные модели контента.** Связанные объекты, ссылки и пользовательские наборы; база данных делает это правильно.
- **Управление.** Роли, редакционные рабочие процессы, штаты модерации контента и требования к аудиту.
- **Масштаб организации.** Многоязычные, многоязычные и многоязычные элементы команды, созревшие по прошествии двух десятилетий.
- **Огромная модульная экосистема** и поддержка долгосрочных предприятий.
- **Персонализация на стороне сервера** и динамическая логика, когда сайт нуждается в ней.

## Где LightCMS побеждает

- **Пропорция.** Для блога, доски или рекламных страниц, Drupal - это завод, покупающий части сборки для мастерской.
- **Нет траекторий для обслуживания.** В статическом выходном выпуске нет патча, нет рекомендаций по модулям и нет пути обновления для плана. Смотрите [статические и динамические сайты](/blog/static-vs-dynamic/).
- **Писатели работают в одиночку.** Разработчик не требуется после установки; браузер - это вся цепочка инструментов.
- **Скорость по умолчанию.** Предварительно отображаемые страницы CDN отображаются на Core Web Vitals с нулевой настройкой.
- **Портализация.** Простой Markdown в Git, читаемый несколько десятилетий.

## Кто на самом деле нуждается в Drupal?

Drupal встраивает организации с регулируемым содержанием, сложными разрешениями, многоязычными требованиями и интегрированными архитектурами. Если вы небольшая командная публикация статей, ни одна из них не применяется, и реальная стоимость Drupal - это экспертиза, которую она требует для жизни сайта, так как лицензия бесплатна.

Если вы находитесь в этой меньшей группе и хотите получить выгоды от владения, мир на основе файлов дает вам такую же прочность ни с одной из операций: [что такое Git на основе CMS? (/blog/git-based-cms-explained/) объясняет модель.

## Миграция

Drupal экспортирует контент через Feeds, Migrate, или его JSON:API. Контент в форме статьи преобразуется в Markdown well; ссылки на сущности, блоки параграфов и списки с движением зрения не делают. Они становятся шаблонами и файлами данных в новом стеке. Ожидать аудит содержимого в рамках любого хода.

## Что Вы выбираете?

- **Выберите Drupal** для сложных, управляемых, сложных сайтов с большой нагрузкой на интеграцию с командой для их сохранения.
- **Выберите LightCMS** для публикаций, где скорость, простота и владельцы определяют результат.

## Часто задаваемые вопросы

### Является ли Drupal перекрывать для блога?

For a straightforward publication, yes. Вы используете фреймворк для выполнения задания папки.

### LightCMS альтернатива Drupal?

Не как платформа: LightCMS не моделирует реляционное содержание. Это альтернатива для варианта публикации Drupal иногда используется.

### Может ли Drupal вывод статических страниц?

Drupal может предварительно визуализировать или сочетаться со статическим экспортом, но приложение и база данных остаются частью архитектуры.

### Что более безопасно?

Статический вывод удаляет время выполнения; безопасность Drupal зависит от сохранения ядра и модулей патча, повторяющихся обязательств.

### Поддерживается ли Drupal?

Да. Это зрелый проект с открытым исходным кодом с активным сообществом. Проверьте текущие графики релизов перед стандартизацией.
