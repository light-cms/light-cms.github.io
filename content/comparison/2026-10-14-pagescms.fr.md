Pages CMS est un CMS basé sur Git centré sur l'édition simple de formulaires sur le contenu du référentiel. Les équipes cherchent des alternatives lorsqu'elles ont besoin d'interfaces d'écriture plus riches, d'édition visuelle, de schémas plus forts, de support Git multi-prestataire ou d'hébergement géré.

## Alternatives en un coup d'œil

| Alternative       | Meilleure forme                                                   | Échange de clé                                                                 |
| :---------------- | :---------------------------------------------------------------- | :----------------------------------------------------------------------------- |
| LightCMS          | Édition visuelle de Markdown pour les sites statiques             | Vérifier l'ensemble des fonctionnalités actuelles et les options d'hébergement |
| Déclencher le CMS | CMS basé sur Git avec des collections basées sur la configuration | Le workflow UI/config peut se sentir daté pour les rédacteurs                  |
| TinaCMS           | Édition visuelle ou structurée avec synchronisation Git           | Nécessite des décisions de schéma/configuration                                |
| Clés statiques    | Schémas de contenu orientés vers le développeur local             | Moins axé sur l'écriture                                                       |
| Sveltia CMS       | Interface CMS basée sur le navigateur léger                       | Projet plus jeune; vérifier l'échéance                                         |
| Canon nuageux     | Gestion de l'édition visuelle des équipes/agences                 | Tarification commerciale                                                       |

## Critères de sélection

Lors de la comparaison des alternatives CMS des pages, évaluez:

- Expérience de modification : champs de formulaire, WYSIWYG, ou édition sur page.
- Support du fournisseur Git : GitHub uniquement ou aussi GitLab/Bitbucket.
- Modèle de contenu : Avant matière/formes, schémas tapés ou blocs structurés.
- Gestion des médias : Téléchargements, chemins de ressources et stockage externe.
- Modèle opérationnel : SaaS hébergé, application auto-hébergée, ou interface statique d'administration.

Pour les équipes qui utilisent déjà Markdown dans Git, la migration est souvent possible sans déplacer le contenu. Le travail principal est de cartographier les champs, les chemins de médias et le flux de travail éditorial.
