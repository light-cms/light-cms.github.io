Git basierte CMS-Tools ermöglichen es Ihnen, Inhalte in einem Browser zu bearbeiten und gleichzeitig den aktuellen Inhalt in einem Git-Repository zu behalten. Dies gibt Ihnen Versionsverlauf, Pull Requests und einfache Dateien, die Sie später verschieben können. Die Schwierigkeit besteht darin, einen zu wählen, weil sie alle „einfache Bearbeitung“ versprechen und sehr unterschiedliche Dinge damit meinen.

Einige sind formbasiert, andere bearbeiten auf der Seite, andere sind für Entwickler gebaut und andere versuchen, das Schreiben für nicht-technische Leute bequemer zu machen. Die richtige Wahl hängt davon ab, wer veröffentlicht wird und wie viel Struktur Ihre Inhalte benötigen.

## Schnellvergleich

| CMS          | Beste für                                             | Stil bearbeiten                        | Zu überprüfende Dinge                                         |
| ------------ | ----------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------- |
| Decap CMS    | Konfigurierte Sammlungen und etablierte Git-Workflows | Formbasierte Admin-UI                  | Aktuelle Wartung, Git-Anbieter, Authentifizierungs-Setup      |
| TinaCMS      | Visual/Kontextbearbeitung                             | On-Page oder strukturierte Bearbeitung | Aktuelle Preise, Selbst-Hosting, Schema-Workflow              |
| Keystatische | Entwickler-definierte Schemas                         | Formulare aus Code generiert           | Aktuelle Framework-Unterstützung, Cloud/lokale Modi           |
| CMS Seiten   | Einfache GitHub Bearbeitung                           | Formularbasiertes Dashboard            | Aktueller Git-Anbieter-Support, Lizenzierung                  |
| Sveltia CMS  | Leichte Browser-Bearbeitung                           | Admin-Oberfläche über Git              | Aktuelle Merkmalsparität und Laufzeit                         |
| Cloudkanone  | Agentur/Client-verwaltete Websites                    | Visuale/redaktionelle Workflows        | Aktuelles Preis- und Hosting-Modell                           |
| LightCMS     | Autoren, die Inhalte der Statik-Site publizieren      | Dokumenten-Editor                      | Aktuelle Funktionen, Hosting, Unterstützung des Git-Providers |

## Wie wählen Sie

Beginnen Sie mit dem Editor, nicht mit der Feature-Liste. Wenn Autoren lange Formulare veröffentlichen, fühlt sich ein Dokumenten-Editor normalerweise besser als ein Formular mit Markdown Textfeld. Wenn Ihre Inhalte strukturierte Datensätze, Formulare und Schemas sind eine bessere Passform.

Als nächstes überprüfen Sie den Projektarchiv-Workflow. Stellen Sie sicher, wohin Bilder gehen, wie Frontmasse behandelt wird, welche Git-Anbieter unterstützt werden, und ob das Tool zu Ihrem statischen Seitengenerator passt. Ein CMS das in einer Demo schön aussieht, kann immer noch ärgerlich sein, wenn es Frontmatter schreibt, die Ihre Vorlagen nicht erwarten.

Und schließlich seien Sie ehrlich in Bezug auf die Operationen. Ein selbst gehostetes Tool gibt dir die Kontrolle, aber du hast eigene Setups und Updates. Ein gehostetes Tool reduziert die Wartung, aber Sie müssen mit Preisgestaltung und Abhängigkeit des Anbieters vertraut sein.

## Wo LightCMS passt

LightCMS ist für Leute, die in einem Browser schreiben wollen und trotzdem den Git-basierten Workflow behalten. Es passt gut, wenn der Hauptjob ist das Publizieren von Artikeln, Docs oder Marketing-Inhalten auf einer statischen Website. Wenn Sie eine datenbankgestützte Content-API, komplexe relationale Content-Modelle, oder eine starke Unternehmensführung benötigen, ist das nicht die richtige Wahl.

Wenn Sie Optionen vergleichen, stoppen Sie nicht bei Featurematrizen. Versuchen Sie die gleiche reale Aufgabe in jedem Werkzeug: Schreiben Sie einen Beitrag, fügen Sie ein Bild, bearbeiten Sie Front-Meile, veröffentlichen, und bestätigen Sie die Website-Builds.
