Git based CMS tools let you edit content in a browser while keeping the actual content in a Git repository. Dies gibt Ihnen Versionsverlauf, Pull Requests und einfache Dateien, die Sie später verschieben können. Die Schwierigkeit besteht darin, einen zu wählen, weil sie alle „einfache Bearbeitung“ versprechen und sehr unterschiedliche Dinge damit meinen.

Some are form-based, some edit on the page, some are built for developers, and some are trying to make writing comfortable for nontechnical people. Die richtige Wahl hängt davon ab, wer veröffentlicht wird und wie viel Struktur Ihre Inhalte benötigen.

## Schnellvergleich

| CMS          | Beste für                                             | Stil bearbeiten                        | Zu überprüfende Dinge                                         |
| ------------ | ----------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------- |
| Decap CMS    | Konfigurierte Sammlungen und etablierte Git-Workflows | Formbasierte Admin-UI                  | Aktuelle Wartung, Git-Anbieter, Authentifizierungs-Setup      |
| TinaCMS      | Visual/Kontextbearbeitung                             | On-Page oder strukturierte Bearbeitung | Aktuelle Preise, Selbst-Hosting, Schema-Workflow              |
| Keystatische | Entwickler-definierte Schemas                         | Formulare aus Code generiert           | Aktuelle Framework-Unterstützung, Cloud/lokale Modi           |
| CMS Seiten   | Einfache GitHub Bearbeitung                           | Formularbasiertes Dashboard            | Aktueller Git-Anbieter-Support, Lizenzierung                  |
| Sveltia CMS  | Leichte Browser-Bearbeitung                           | Admin-Oberfläche über Git              | Aktuelle Merkmalsparität und Laufzeit                         |
| Cloudkanone  | Agentur/Client-verwaltete Websites                    | Visuale/redaktionelle Workflows        | Aktuelles Preis- und Hosting-Modell                           |
| LightCMS     | Autoren, die Inhalte der Statik-Site publizieren      | Dokumenten-Editor                      | Aktuelle Funktionen, Hosting, Unterstützung des Git-Providers |

## Wie wählen Sie

Beginnen Sie mit dem Editor, nicht mit der Feature-Liste. If writers are publishing long-form articles, a document editor usually feels better than a form with a Markdown text area. Wenn Ihre Inhalte strukturierte Datensätze, Formulare und Schemas sind eine bessere Passform.

Als nächstes überprüfen Sie den Projektarchiv-Workflow. Stellen Sie sicher, wohin Bilder gehen, wie Frontmasse behandelt wird, welche Git-Anbieter unterstützt werden, und ob das Tool zu Ihrem statischen Seitengenerator passt. Ein CMS das in einer Demo schön aussieht, kann immer noch ärgerlich sein, wenn es Frontmatter schreibt, die Ihre Vorlagen nicht erwarten.

Und schließlich seien Sie ehrlich in Bezug auf die Operationen. Ein selbst gehostetes Tool gibt dir die Kontrolle, aber du hast eigene Setups und Updates. Ein gehostetes Tool reduziert die Wartung, aber Sie müssen mit Preisgestaltung und Abhängigkeit des Anbieters vertraut sein.

## Wo LightCMS passt

LightCMS is for people who want to write in a browser and still keep the Git based workflow. Es passt gut, wenn der Hauptjob ist das Publizieren von Artikeln, Docs oder Marketing-Inhalten auf einer statischen Website. It’s not the right fit when you need a database based content API, complex relational content models, or heavy enterprise governance.

Wenn Sie Optionen vergleichen, stoppen Sie nicht bei Featurematrizen. Versuchen Sie die gleiche reale Aufgabe in jedem Werkzeug: Schreiben Sie einen Beitrag, fügen Sie ein Bild, bearbeiten Sie Front-Meile, veröffentlichen, und bestätigen Sie die Website-Builds. Das sagt Ihnen schnell, welche man zu Ihrem Team passt. See [Git based CMS vs Traditional CMS](/blog/git-cms-vs-traditional-cms/) and [Getting Started with LightCMS](/getting-started/).
