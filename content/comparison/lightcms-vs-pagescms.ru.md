LightCMS и страницы CMS хранят ваш контент как файлы в Git, поэтому вы никогда не теряете права собственности на ваш репозиторий. Реальное разделение состоит в том, что вы проводите большую часть времени редактирования: длинные статьи Markdown или структурированные передние поля вещей.

Страницы CMS содержат поля формы и схемы коллекции, а LightCMS сначала помещает визуальный редактор документов.

## Как сравниваются редактируемые модели

| Область                     | LightCMS                                                                        | Страницы CMS                                                                 |
|:--------------------------- |:------------------------------------------------------------------------------- |:---------------------------------------------------------------------------- |
| Основной интерфейс          | TipTap визуальный редактор Markdown                                             | Редактор форм, управляемый конфигурацией                                     |
| Лучший подбор               | Долгосрочные статьи, документы и эссе                                           | Структурированные записи, каталоги и записи с большим количеством метаданных |
| Хранилище содержимого       | Markdown с передним вопросом в GitHub                                           | Файлы и медиа в GitHub                                                       |
| Конфигурация                | GitHub App соединение (требуется PostgreSQL, если самохостинг)                  | Файл конфигурации репозитория, определяющий коллекции и поля                 |
| Написание рабочего процесса | Черновики, форматирование, вставка изображения, черновик AI, диктограмма голоса | Проверка полей, выбор, даты и ввод текста                                    |

Это различие показывает момент открытия должности: LightCMS чувствует себя как письменный стол, В то время как CMS чувствует себя как администраторская форма над вашим репозиторием.

## Когда страницы CMS лучше выбрать

Страницы CMS имеют больше смысла, когда ваш сайт строится вокруг структурированных записей, а не длинной прозы. Если вы работаете с каталогами, журналами изменений, списками продуктов или страницами, где настраиваются даты, выбираются логические файлы, и вложенные поля переднего материала больше всего, определяя эти схемы в конфигурационном файле не позволяет редакторам ломать вашу сборку.

Также легче использовать, если вы не хотите запускать базу данных приложений для самой CMS.

## Когда LightCMS лучше выбрать

LightCMS лучше подходит, когда основная работа - написание и редактирование статей. Если вы или ваши писатели тратят большую часть дня на составление 1 000 сообщений с заголовками, блоками кода, таблицами, и встроенные изображения, браузерный редактор документов теряет путь быстрее, чем стек ввода формы.

Перед выбором инструмента протестируйте как по вашему фактическому формату репозитория, так и по формату передней части и по папке с изображениями.
