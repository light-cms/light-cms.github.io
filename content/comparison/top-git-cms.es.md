Las herramientas CMS basadas en Git le permiten editar el contenido en un navegador mientras mantiene el contenido real en un repositorio Git. Esto le da historial de versiones, pull requests y archivos simples que puede mover más tarde. La parte difícil es elegir una, porque todos prometen “edición fácil” y significan cosas muy diferentes con ella.

Algunas están basadas en formularios, otras en la página, otras están construidas para desarrolladores, y otras están tratando de hacer que la escritura sea cómoda para personas no técnicas. La elección correcta depende de quién está publicando y de cuánta estructura necesita tu contenido.

## Comparación rápida

| CMS            | Mejor para                                                       | Editando estilo                            | Cosas a comprobar                                                        |
| -------------- | ---------------------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------ |
| Decaer CMS     | Colecciones configuradas y flujos de trabajo de Git establecidos | IU de administración basada en Formularios | Mantenimiento actual, proveedores de Git, configuración de autenticación |
| TinaCMS        | Edición visual/contextual                                        | Edición en página o estructurada           | Precio actual, autoalojamiento, flujo de trabajo del esquema             |
| Llave estática | Esquemas definidos por el desarrollador                          | Formularios generados a partir del código  | Soporte actual del framework. Modos nube/local                           |
| Páginas CMS    | Edición simple de GitHub                                         | Panel basado en formato                    | Soporte actual del proveedor de Git, licencias                           |
| Sveltia CMS    | Edición ligera del navegador                                     | IU de admin sobre Git                      | Paridad actual de características y madurez                              |
| Cañón nube     | Sitios administrados por la agencia/cliente                      | Flujos de trabajo visuales/editoriales     | Modelo actual de precio y alojamiento                                    |
| LightCMS       | Escritores publicando contenido estático del sitio               | Editor de documentos                       | Características actuales, alojamiento, soporte para proveedores de Git   |

## Cómo elegir

Comenzar con el editor, no con la lista de características. Si los escritores están publicando artículos de forma larga, un editor de documentos normalmente se siente mejor que un formulario con un área de texto de Markdown. Si su contenido está estructurado, los formularios y esquemas son más adecuados.

A continuación, compruebe el flujo de trabajo del repositorio. Confirme dónde van las imágenes, cómo se maneja la materia frontal, qué proveedores de Git son soportados, y si la herramienta se ajusta a su generador de sitio estático. Un CMS que se vea bien en una demostración puede ser aún molesto si escribe la materia frontal que sus plantillas no esperan.

Por último, seamos sinceros con respecto a las operaciones. Una herramienta autoalojada le da control, pero usted posee configuración y actualizaciones. Una herramienta alojada reduce el mantenimiento, pero necesita estar cómodo con los precios y la dependencia del vendedor.

## Donde encaja LightCMS

LightCMS es para personas que quieren escribir en un navegador y mantener el flujo de trabajo basado en Git. Se ajusta bien cuando el trabajo principal es publicar artículos, documentos o contenido de marketing en un sitio estático. No es el ajuste adecuado cuando se necesita una API de contenido basada en bases de datos, modelos de contenido relacional complejos o una gobernanza empresarial pesada.

Si estás comparando opciones, no te detienes en las matrículas de características. Pruebe la misma tarea real en cada herramienta: escriba una publicación, añada una imagen, edite la materia delantera, publique y confirme las versiones del sitio.
