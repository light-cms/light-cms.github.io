TinaCMS and LightCMS both save content as Markdown in your Git repository. The big difference is where you do the editing. TinaCMS lets you click into the rendered page and edit in context. LightCMS gives you a separate writing space where the document is the focus.

Neither approach is wrong. It depends on whether you're fixing a headline on a landing page or writing a 2,000-word article.

## Two ways to edit

With TinaCMS, you edit on the page itself. That’s great when layout matters: you can see immediately whether a headline is too long for its box or whether a short description fits a card.

With LightCMS, you edit in a document workspace. That’s calmer for long-form writing because you’re not scrolling past hero images and layout blocks to reach paragraph fourteen. You write, format, add images, and publish.

| | LightCMS | TinaCMS |
|---|---|---|
| Editing model | Standalone document editor | On-page/contextual editing |
| Content storage | Git repository | Git repository |
| Schema | Managed in the app | Defined in code/config |
| Best for | Articles, docs, changelogs | Landing pages, page copy, component-driven sites |
| AI drafting | Built in | Not bundled |
| Voice dictation | Built in | Not bundled |

## When TinaCMS makes more sense

TinaCMS is handy when content lives inside a designed page. If you’re editing marketing copy, component props, or page sections where layout matters, seeing the real page while you edit is useful. Its schema-in-code model also fits developer teams that want content structure reviewed like code.

## When LightCMS makes more sense

LightCMS is better when the writing itself is the job. Drafting articles, docs, and release notes is easier in a document editor than in a page full of layout components. It also keeps front matter manageable for non-developers, so a writer doesn’t need to open a pull request just to add a field.

## Choosing between them

Pick TinaCMS if your team thinks in pages and components and is comfortable managing content schema in code. Pick LightCMS if your team thinks in articles and wants writers to work without developer help. Tina gives you context; LightCMS gives you focus.

An easy test: try editing the same piece of content in both styles. If you keep wanting to see the layout, Tina’s model fits. If you keep wanting fewer distractions, LightCMS probably does.
