Sowohl LightCMS als auch Pages CMS speichern Ihre Inhalte als Dateien in Git, so dass Sie nie verlieren das Eigentum an Ihrem Projektarchiv. Die eigentliche Spaltung liegt in dem, was Sie die meiste Zeit in der Bearbeitung verbringen: Langform-Markdown-Artikel oder strukturierte Frontbereiche.

Auf Seiten CMS werden Formularfelder und Sammlungsschemas erstellt, während LightCMS zuerst einen Editor für visuelle Dokumente erstellt.

## Wie die Bearbeitungsmodelle vergleichen

| Fläche                         | LightCMS                                                                      | CMS Seiten                                                               |
|:------------------------------ |:----------------------------------------------------------------------------- |:------------------------------------------------------------------------ |
| Primäre Schnittstelle          | TipTippen visueller Markdown Editor                                           | Config-gesteuerter Formular-Editor                                       |
| Beste Passung                  | Artikel, Dokumente und Essays mit langer Form                                 | Strukturierte Datensätze, Kataloge und Metadaten-schwere Einträge        |
| Inhaltsspeicher                | Markdown mit Frontmasse in GitHub                                             | Dateien und Medien in GitHub                                             |
| Konfiguration                  | GitHub App-Verbindung (PostgreSQL wird benötigt, wenn du dich selbst hostest) | Repository-Konfigurationsdatei zur Definition von Sammlungen und Feldern |
| Arbeitsablauf wird geschrieben | Entwürfe, Formatierung, Bildeinfügung, KI-Entwurf, Sprachdiktatur             | Feldvalidierung, Auswahl, Datum und Rich-Text-Eingaben                   |

Dieser Unterschied zeigt an, wenn Sie einen Beitrag öffnen: LightCMS fühlt sich wie ein Schreibtisch an, während sich Pages CMS wie ein Admin-Formular über Ihrem Repository anfühlt.

## Wenn Seiten CMS die bessere Wahl ist

Pages CMS macht mehr Sinn, wenn Ihre Website um strukturierte Datensätze aufgebaut ist und nicht um Langformprose. Wenn Sie Verzeichnisse, Changelogs, Produktlisten oder Seiten verwalten, auf denen benutzerdefinierte Daten, Auswahlen, Booleans, und verschachtelte Front-Match-Felder sind am meisten von Bedeutung, die Definition dieser Schemas in einer Konfigurationsdatei hindert Redakteure daran, Ihre Build zu brechen.

Es ist auch leichter anzunehmen, wenn Sie keine Anwendungsdatenbank für das CMS selbst ausführen möchten.

## Wenn LightCMS die bessere Wahl ist

LightCMS passt besser, wenn der Hauptauftrag Artikel verfasst und editiert. Wenn Sie oder Ihre Schriftsteller den größten Teil des Tages verbringen, schreiben Sie 1000 Wörter mit Überschriften, Codeblöcken, Tabellen, und Inline-Images wird ein browserbasierter Dokumenten-Editor schneller aus als ein Stapel von Formulareingaben.

Bevor Sie ein Werkzeug wählen, testen Sie sowohl gegen Ihr aktuelles Projektarchiv-Layout, das Frontmatter Format als auch die Konventionen für den Bildordner.
