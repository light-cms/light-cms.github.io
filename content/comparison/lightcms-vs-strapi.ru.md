Strapi и LightCMS являются как открытыми так и самохостами, но они хранят контент в очень разных местах. Strapi - это бесконечная CMS: контент идет в базу данных и выходит через REST или GraphQL API. LightCMS является редактором на основе Git: содержимое попадает в файлы Markdown в вашем хранилище и встраивается в статический сайт.

Это одно отличие приводит к большей части из других: взлетно-посадочная полоса, стоимость, версия, и сколько инфраструктур вам нужно поддерживать здоровье.

## Рядом

|                       | LightCMS                 | Strapi                                 |
| --------------------- | ------------------------ | -------------------------------------- |
| Хранилище содержимого | Markdown файлы в Git     | Database (SQLite/Postgres/MySQL)       |
| Доставка              | Статическая сборка в CDN | REST/GraphQL API во время выполнения   |
| Рунтайм               | Нет по запросу           | Node.js приложение и база данных       |
| Модель контента       | Передние поля            | Типы контента в админе                 |
| Versioning            | Git history              | Создание/публикация и изменения        |
| Лучше для             | Статические публикации   | Приложения, нуждающиеся в API контента |
| Лицензия              | Apache 2.0               | MIT/Enterprise editions                |

## Когда Strapi имеет больше смысла

Strapi является хорошим дополнением, когда контент должен действовать как данные приложения. Если у вас есть реляционные типы содержимого, необходимо API для нескольких интерфейсов, нужна пользовательская логика backend, или нужны рабочие процессы на основе ролей в панели администрирования, CMS с поддержкой базы данных является правильной формой.

Это также полезно, когда изменения должны вступить в силу немедленно, не дожидаясь статической сборки.

## Когда LightCMS имеет больше смысла

LightCMS хорошо подходит, когда вы публикуете сайт, а не запускаете платформу для контента. Статьи, документация, журнал изменений и маркетинговые страницы, а также файлы Markdown. Вы получаете Git историю, статическую доставку и нет базы данных для резервного копирования или патча.

Опыт написания также прост: открыть документ, писать, издать. Вам не нужно думать о типах контента, конечных точках API или CMS сервере.

## Выбор между ними

Выберите Strapi, если вам нужен контент API и структурированный, реляционный контент. Выберите LightCMS если вы хотите простой издательский рабочий процесс для статического сайта. Strapi предоставляет Вам гибкость, но Вы платите за это в операциях. LightCMS дает вам простоту и переносимость, но это не тот инструмент, когда ваш контент нуждается в запросе подобных данных.

Если вы создаете блог или сайт docs, я бы запустил простоту. Вы всегда можете перейти на безголовый CMS позже, если вам действительно нужен API. Другими словами, затянуть в файлы модель содержимого базы данных, как правило, труднее. См.
