Git based CMS tools let you edit content in a browser while keeping the actual content in a Git repository. Isso lhe dá histórico de versões, pull requests e arquivos simples que você pode mover mais tarde. A parte difícil é escolher uma, porque todos prometem "edição fácil" e significam coisas muito diferentes com ela.

Some are form-based, some edit on the page, some are built for developers, and some are trying to make writing comfortable for nontechnical people. A escolha certa depende de quem está publicando e quanta estrutura seu conteúdo precisa.

## Comparação rápida

| SGC             | Melhor para                                                  | Estilo de edição                       | Coisas para verificar                                          |
| --------------- | ------------------------------------------------------------ | -------------------------------------- | -------------------------------------------------------------- |
| Decapitar CMS   | Coleções configuradas e fluxos de trabalho Git estabelecidos | Interface admin baseada em formulários | Manutenção atual, provedores Git, configuração de autenticação |
| TinaCMS         | Edição de contexto/visualização                              | Edição estruturada ou na página        | Preços atuais, auto-hospedagem, fluxo de trabalho de esquema   |
| Keystatica      | Programas definidos pelo desenvolvedor                       | Formulários gerados a partir do código | Suporte a framework atual, modos em nuvem/local                |
| CMS das Páginas | Edição simples de GitHub                                     | Painel baseado em formulário           | Suporte atual do provedor Git, licenciamento                   |
| Sveltia CMS     | Edição de navegador leve                                     | Interface do Administrador sobre Git   | Paridade e maturidade de recursos atuais                       |
| Canhão Nublado  | Sites de agência/cliente gerenciados                         | Workflows visuais/editoriais           | Modelo atual de preço e hospedagem                             |
| CMS             | Editores publicando conteúdo estático do site                | Editor de documentos                   | Recursos atuais, suporte ao provedor Git                       |

## Como escolher

Comece com o editor, não com a lista de recursos. If writers are publishing long-form articles, a document editor usually feels better than a form with a Markdown text area. Se o seu conteúdo for um registro estruturado, formulários e esquemas mais adequado.

Em seguida, verifique o fluxo de trabalho do repositório. Confirme onde as imagens vão, como a matéria frontal é tratada, quais provedores do Git são suportados e se a ferramenta se encaixa ao seu gerador de site estático. Um CMS que fique bonito em uma demonstração ainda pode ser irritante se escrever na página inicial seus modelos não esperados.

Por último, sejamos honestos no que respeita às operações. Uma ferramenta auto-hospedada lhe dá controle mas você possui configurações e atualizações. Uma ferramenta hospedada reduz a manutenção, mas você precisa estar confortável com os preços e a dependência do fornecedor.

## Onde o CMS se encaixa

LightCMS is for people who want to write in a browser and still keep the Git based workflow. Ele se encaixa bem quando a tarefa principal é publicar artigos, documentos ou marketing de conteúdo em um site estático. It’s not the right fit when you need a database based content API, complex relational content models, or heavy enterprise governance.

Se você estiver comparando as opções, não pare nas matrizes de recursos. Tente a mesma tarefa real em cada ferramenta: escrever um post, adicionar uma imagem, editar front, publicar e confirmar as compilações do site. Isso te diz rapidamente qual deles serve ao seu time.
