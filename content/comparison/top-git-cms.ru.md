Инструменты CMS на основе Git позволяют редактировать содержимое в браузере при сохранении фактического содержимого в Git-репозитории. Это дает вам историю версий, Pull Request и простые файлы, которые вы можете переместиться позже. Тяжелая часть выбирает один, потому что они обещают «легкое редактирование» и обозначают его очень разные вещи.

Некоторые из них основаны на форме, некоторые правки на странице, некоторые из них созданы для разработчиков, а некоторые пытаются сделать запись удобной для нетехнических людей. Правильный выбор зависит от того, кто публикует и сколько структурирует ваш контент.

## Быстрое сравнение

| CMS              | Лучше для                                                  | Редактировать стиль                              | Что нужно проверить                                         |
| ---------------- | ---------------------------------------------------------- | ------------------------------------------------ | ----------------------------------------------------------- |
| Разрезать CMS    | Настроенные коллекции и установленные Git рабочие процессы | Панель администратора                            | Текущее обслуживание, Git провайдеры, настройка авторизации |
| TinaCMS          | Визуальное/контекстное редактирование                      | На странице или структурированном редактировании | Текущая цена, самохостинг, схема рабочего процесса          |
| Ключевая статика | Определенные разработчиком схемы                           | Формы, созданные из кода                         | Поддержка текущего фреймворка, облачные/локальные режимы    |
| Страницы CMS     | Простое редактирование GitHub                              | Панель управления                                | Поддержка текущего поставщика Git, лицензирование           |
| Sveltia CMS      | Легкое редактирование браузера                             | Администратор над Git                            | Четность текущей функции и степень зрелости                 |
| Облачная Пушка   | Сайты, управляемые агентством/клиентом                     | Визуальные/редакционные процессы                 | Текущая модель ценообразования и хостинга                   |
| LightCMS         | Публикация контента статического сайта писателями          | Редактор документов                              | Текущие возможности, хостинг, поддержка Git провайдеров     |

## Как выбрать

Начните с редактора, а не со списка. Если писатели публикуют длинные статьи, редактор документов обычно чувствует себя лучше, чем форма с текстовой областью Markdown . Если ваш контент структурирован, формы и схемы лучше подходит.

Далее проверьте процесс работы репозитория. Проверьте, куда идут изображения, как обрабатывается передняя часть, какие поставщики Git поддерживаются, и соответствует ли инструмент вашему статическому создателю сайта. CMS с красивым демо может быть раздражающим, если он пишет фронт-версию шаблонов не ожидать.

Наконец, будьте честны в отношении операций. Инструмент само-хостинга дает вам управление, но вы владеете установкой и обновлениями. Хостинг сокращает расходы на техническое обслуживание, но вам нужно быть комфортным с точки зрения цен и зависимости от поставщика.

## Где подходят LightCMS

LightCMS для людей, которые хотят писать в браузере и все еще держать на основе Git рабочий процесс. Она хорошо подходит, когда основной задачей является публикация статических статей, документов или маркетинговых материалов на статический сайт. Это не правильно, когда вам нужен API контента базы данных, сложные реляционные модели контента или тяжелое управление предприятием.

Если вы сравниваете параметры, не останавливайтесь на функциональной матрице. Попробуйте одну и ту же реальную задачу в каждом инструменте: написать пост, добавить изображение, редактировать переднюю тему, опубликовать и подтвердить сборки сайта. Это говорит вам быстро, какой из них подходит для вашей команды. См. [Git based CMS vs Traditional CMS](/blog/git-cms-vs-traditional-cms/) и [Getting Started with LightCMS](/getting-started/).
