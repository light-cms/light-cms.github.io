Git based CMS tools let you edit content in a browser while keeping the actual content in a Git repository. Это дает вам историю версий, Pull Request и простые файлы, которые вы можете переместиться позже. Тяжелая часть выбирает один, потому что они обещают «легкое редактирование» и обозначают его очень разные вещи.

Some are form-based, some edit on the page, some are built for developers, and some are trying to make writing comfortable for nontechnical people. Правильный выбор зависит от того, кто публикует и сколько структурирует ваш контент.

## Как выбрать

Начните с редактора, а не со списка. If writers are publishing long-form articles, a document editor usually feels better than a form with a Markdown text area. Если ваш контент структурирован, формы и схемы лучше подходит.

Далее проверьте процесс работы репозитория. Проверьте, куда идут изображения, как обрабатывается передняя часть, какие поставщики Git поддерживаются, и соответствует ли инструмент вашему статическому создателю сайта. CMS с красивым демо может быть раздражающим, если он пишет фронт-версию шаблонов не ожидать.

Наконец, будьте честны в отношении операций. Инструмент само-хостинга дает вам управление, но вы владеете установкой и обновлениями. Хостинг сокращает расходы на техническое обслуживание, но вам нужно быть комфортным с точки зрения цен и зависимости от поставщика.

## Где подходят LightCMS

LightCMS is for people who want to write in a browser and still keep the Git based workflow. Она хорошо подходит, когда основной задачей является публикация статических статей, документов или маркетинговых материалов на статический сайт. It’s not the right fit when you need a database based content API, complex relational content models, or heavy enterprise governance.

Если вы сравниваете параметры, не останавливайтесь на функциональной матрице. Попробуйте одну и ту же реальную задачу в каждом инструменте: написать пост, добавить изображение, редактировать переднюю тему, опубликовать и подтвердить сборки сайта. Это говорит вам быстро, какой из них подходит для вашей команды. See [Git based CMS vs Traditional CMS](/blog/git-cms-vs-traditional-cms/) and [Getting Started with LightCMS](/getting-started/).
