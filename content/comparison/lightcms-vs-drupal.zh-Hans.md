LightCMS和Drupal服务于不同规模的内容管理。 LightCMS是基于 Git 的静态站点内容，通常是在仓库中Markdown 的工作流。 Drupal 是基于 PHP 的 CMS 框架，用于复杂的内容模型、权限和可扩展性。

## 比较

| 区域   | LightCMS        | 迪帕尔             |
| :--- | :-------------- | :-------------- |
| 结构   | Git 文件 + 静态站点版本 | PHP 应用程序 + 数据库  |
| 内容模型 | 以文件/前事项为重点      | 实体、 字段、 分类法、 模块 |
| 治理   | Git/repo 工作流    | 颗粒式角色，工作流，权限    |
| 维护费  | 内容和构建管道         | 核心模块，安全模块，主机维护  |
| 最合适的 | 博客、文档、营销网站      | 复杂的组织或企业站点      |

## 二者之间的选择

当您需要复杂的内容模型、精细的权限、多语言工作流或 CMS 行为开始看起来像应用程序时，Drupal 是有道理的。这是为拥有开发者和支持者的组织建立的。

当网站主要是出版物时，LightCMS是有意义的。如果你想要静态送货、仓库中的内容以及更简单的写工作流程，你不需要Drupal的权重。

对于一个小的出版站，Drupal可以成为大量的工作基础设施。对于一个要求复杂的大型组织，LightCMS可能会感到过于有限。 See [LightCMS vs WordPress](/comparison/lightcms-vs-wordpress) and [Static vs. Dynamic Sites](/blog/static-vs-dynamic/).
