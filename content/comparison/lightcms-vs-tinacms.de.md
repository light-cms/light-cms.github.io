TinaCMS und LightCMS speichern beide Inhalte als Markdown in Ihrem Git-Repository. Der große Unterschied besteht darin, wo Sie die Bearbeitung durchführen. Mit TinaCMS können Sie in die gerenderte Seite klicken und im Kontext bearbeiten. LightCMS bietet Ihnen einen separaten Schreibraum, in dem das Dokument im Mittelpunkt steht.

Beides ist nicht falsch. Es hängt davon ab, ob Sie eine Überschrift auf einer Landingpage fixieren oder einen 2.000 Wort-Artikel schreiben.

## Zwei Wege zu bearbeiten

Mit TinaCMS bearbeiten Sie die Seite selbst. Das ist großartig, wenn es um das Layout geht: Man sieht sofort, ob eine Überschrift zu lang ist oder ob eine kurze Beschreibung zu einer Karte passt.

Mit LightCMS bearbeiten Sie in einem Dokumenten-Arbeitsbereich. Das ist ruhiger für das Langform-Schreiben, da du nicht an Heldenbildern und Layoutblöcken vorbeiscrollst um Absatz 14 zu erreichen. Sie schreiben, Format, Bilder hinzufügen und veröffentlichen.

|                   | LightCMS                              | TinaCMS                                                |
| ----------------- | ------------------------------------- | ------------------------------------------------------ |
| Modell bearbeiten | Editor für eigenständige Dokumente    | On-page/kontext-Bearbeitung                            |
| Inhaltsspeicher   | Git Repository                        | Git Repository                                         |
| Schema            | In der App verwaltet                  | Definiert in Code/Config                               |
| Beste für         | Beiträge, Bilder, Änderungsprotokolle | Startseiten, Seitenkopie, komponentengesteuerte Seiten |
| KI-Entwurf        | Eingebaut in                          | Nicht gebündelt                                        |
| Sprachdiktatur    | Eingebaut in                          | Nicht gebündelt                                        |

## Wenn TinaCMS mehr Sinn macht

TinaCMS ist praktisch, wenn Inhalte innerhalb einer entworfenen Seite leben. Wenn Sie Marketing-Kopien, Komponenten-Requisiten oder Seitenabschnitte bearbeiten, auf deren Layout es ankommt, ist es nützlich, die Originalseite während der Bearbeitung zu sehen. Sein Schema-in-Code-Modell passt auch zu Entwicklerteams, die eine inhaltliche Struktur wie Code überprüfen wollen.

## Wenn LightCMS mehr Sinn macht

LightCMS ist besser, wenn das Schreiben selbst ist die Aufgabe. Das Erstellen von Artikeln, Docs und Release-Notizen ist in einem Dokumenten-Editor einfacher als auf einer Seite voller Layout-Komponenten. Es hält auch die Frontmasse für Nicht-Entwickler beherrschbar, so dass ein Schriftsteller nicht einen Pull-Request öffnen muss, nur um ein Feld hinzuzufügen.

## Wählen Sie zwischen ihnen

Wählen Sie TinaCMS aus, wenn Ihr Team an Seiten und Komponenten denkt und das Inhaltsschema im Code komfortabel verwaltet. Wählen Sie LightCMS aus, wenn Ihr Team in Artikeln denkt und möchte, dass Autoren ohne Entwicklerhilfe arbeiten. Tina gibt Ihnen Kontext; LightCMS gibt Ihnen den Fokus.

Ein einfacher Test: Versuchen Sie, die gleichen Inhalte in beiden Stilen zu bearbeiten. Wenn Sie das Layout immer wieder sehen wollen, passt Tina zum Modell. Wenn Sie immer weniger Ablenkungen wollen, ist LightCMS wahrscheinlich der Fall.
