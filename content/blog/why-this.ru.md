Мы строим [LightCMS](https://lightcms.me), потому что публикация на статическом сайте не должна требовать от каждого писателя следить за рабочим процессом разработчика. Вы можете писать в редакторе браузера, а содержимое остается в Git как файлы Markdown.

## Проблема со статическими издательскими процессами

Статические генераторы сайтов делают его простым для создания и развертывания сайта. Написание одного может по-прежнему означать клонирование репозитория, редактирование Markdown, управление передней частью, фиксация и ожидание CI/CD.

Это знакома территория для застройщиков. Для писателей и редакторов он может получить в порядке публикации.

## Почему Git основанный на контенте по-прежнему имеет важное значение

Сохранение содержания в Git дает вам несколько практических вещей:

- История изменений, которые вы можете просматривать, сравнивать или откатить.
- Markdown файлы можно перемещать между генераторами, хостами и редакторами.
- Прямой путь к Git для создания и развертывания рабочих процессов многие статические сайты уже используются.
- Копия вашего контента в вашем собственном хранилище, а не в базе данных CMS.

## Что дает LightCMS

LightCMS построен на основе публикации из Git, а не из реального времени. Это хорошо работает для блогов, документации и маркетинговых сайтов. Если вам нужна персонализация, сложные связи между содержанием или запросами к базе данных во время выполнения, то лучше подойдет другой вид CMS .

Вы пишете в визуальном редакторе, в то время как файлы Markdown и Git остаются источником истины. Подробнее о продукте смотрите [Что такое LightCMS?](/blog/what-is-lightcms/).
