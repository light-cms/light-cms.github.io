Вы можете уведомлять читателей о новых сообщениях из Git в блоге без использования отдельной платформы маркетинга электронной почты. [Newsy](https://github.com/light-cms/newsy) использует GitHub репозиторий и подписку на рассылку обновлений через GitHub.

## Там, где традиционные инструменты рассылки добавляют накладные

Электронные информационные платформы могут быть полезными, но они добавляют операционную работу для небольших технических блогов:

1. Управление списками: Вы сохраняете данные абонента в отдельной системе.
2. Повторяющаяся публикация: Часто вы копируете запись Markdown в редактор электронной почты или шаблон.
3. Операции обеспечения работоспособности: Вы отслеживаете отказы, жалобы на спам, репутацию отправителя и протоколы аутентификации, такие как SPF, DKIM и DMARC.
4. Решения по отслеживанию и конфиденциальности: Многие платформы включают открытое отслеживание, отслеживание кликов и отписку от управления, которое необходимо для настройки и раскрытия.

Для блога, ориентированного на разработчиков, эти функции могут быть больше, чем рабочие процессы. Торговля заключается в том, что вы отказываетесь от автоматизации маркетинга, сегментации и аналитики.

## Как Ньюси использует GitHub уведомления

Newsy соединяет события публикации в GitHub репозитории с темой подписки. Приведенный ниже рабочий процесс описывает предполагаемую модель; перед тем как рассматривать ее в качестве документации к продукту, проверяйте каждый шаг в сравнении с текущей реализацией Ньюси.

```text
Writer публикует в LightCMS
 <unk>
 <unk>
 Записано в GitHub репозиторий
 <unk>
 <unk>
Newsy обнаруживает новый или недавно опубликованный пост
 <unk>
 <unk>
Новостей комментарий к объявлению
 <unk>
 <unk>
GitHub уведомляет пользователей, подписавшихся на эту проблему
```

### Шаги доставки

1. Определение коммита: Публикация действия создает или обновляет Markdown файл в репозитории. Newsy can watch for a new post or a `draft: false` Change.
2. Объявление: Newsy пишет обновление выделенной проблемы с GitHub, например, об `объявлении` с меткой `информационного бюллетеня`.
3. Подписка на чтение: читатели подписываются, просматривая или подписываясь на этот выпуск GitHub.
4. Отправка уведомлений: GitHub отправляет уведомления на основе настроек уведомлений каждого абонента.

## Сделки для рассмотрения

Такой подход лучше соответствует технической аудитории, чем общей аудитории.

- Требуется учетная запись GitHub: Читателям нужна учетная запись GitHub, чтобы подписаться. Это разумно для многих блогов разработчиков, но он может блокировать нетехнических читателей.
- Обычный формат уведомлений: GitHub уведомления не являются заменой фирменных маркетинговых писем. Вы имеете ограниченный контроль над разметкой и стилем.
- Ограниченная аналитика: Вы не получаете типичные показатели маркетинга электронной почты, такие как открытый тариф или скорость перехода. Вы можете проверить участие в обсуждении, но это не то же самое, что и аналитика кампании.

## Настройка чек-листа

1. Install Newsy: Добавьте [Newsy GitHub App](https://github.com/apps/newsletter-newsy/installations/select_target) в репозиторий, который содержит ваш блог.
2. Создайте точку входа в подписку: создайте или создайте ссылку на подписку/кнопку, которая указывает читателям на выпуск объявления.
3. Добавьте ссылку на свой сайт: разместите ссылку подписки в макете блога, футере или шаблоне записи.
4. Тест потока: Опубликуйте черновик, подтвердите коммит, подтвердите комментарий задачи и убедитесь, что подписанный аккаунт получает уведомление.
