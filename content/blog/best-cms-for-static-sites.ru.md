Лучшие CMS для статического сайта зависят от того, где живет ваш контент и кому необходимо его редактировать. Инструменты CMS на основе Git хорошо работают, когда вы хотите, чтобы Markdown файлы в системе управления версиями; совместимые с базами данных инструменты CMS лучше работают, если вам нужен реляционный контент, runtime API или сложные разрешения.

## Параметры архитектуры CMS

| Архитектура                       | Хранилище содержимого                  | Хороший подбор                                      | Главный трейд-офф                                                  |
| :-------------------------------- | :------------------------------------- | :-------------------------------------------------- | :----------------------------------------------------------------- |
| Редактор документов на основе Git | Markdown файлы в Git                   | Блоги, документация, маркетинговые сайты            | Ограниченное время выполнения запросов и реляционное моделирование |
| Администрирование на основе Git   | Файлы в Git, редактировать через формы | Структурированный контент с фиксированными полями   | Меньше естественной для длительной записи                          |
| Визуальный/редактор страницы      | Git или внешнее хранилище              | Целевые страницы и жесткий контент                  | Высокая настройка и интеграция                                     |
| Без заголовков CMS                | База данных с API доставкой            | Приложения и сложные схемы, многоканальная доставка | Повышение инфраструктуры и блокировка продавца риска               |

## Опции CMS для оценки

Приведенные ниже инструменты являются общими параметрами в рабочих потоках статического сайта. Функция изменяется, поэтому рассматривайте это как начальный короткий список и верифицируйте детали в официальной документации.

### LightCMS

[LightCMS](https://lightcms.me) — это CMS основанный на Git, фокусирующийся на редактировании Markdown контента в репозитории. Хорошо подходит, когда вы хотите, чтобы писатели использовали визуальный редактор в то время как разработчики сохраняют сборку и развертывание.

### Разрезать CMS

[Decap CMS](https://decapcms.org/) — это Git CMS основанный на браузере через конфигурационный файл репозитория. Он подходит для команд, которым нужна простая панель администратора над Markdown или структурированные файлы содержимого.

### TinaCMS

[TinaCMS](https://tina.io/) обеспечивает визуальное редактирование рабочих процессов и контента на основе Git для поддерживаемых настроек интерфейса. Это полезно, когда редакторам необходимо предварительно просматривать содержимое в контексте.

### Ключевая статика

[Keystatic](https://keystatic.com/) — это основанная на Git CMS, ориентированная на разработанные разработчиком схемы и локальные рабочие процессы. Он может соответствовать Astro и Next.js проектам, в которых разработчики хотят напечатать модели контента.

### Страницы CMS

[Страницы CMS](https://pagescms.org/) предоставляет веб-интерфейс для редактирования содержимого репозитория через конфигурацию. Он полезен для простого Git редактирования без создания пользовательского админа.

### Sveltia CMS

[Sveltia CMS](https://github.com/sveltia/sveltia-cms) призвана обеспечить современную альтернативу декапу рабочих потоков в стиле CMS. Она может быть привлекательна для команд, переходящих из конфигураций Decap.

### Облачная Пушка

[CloudCannon](https://cloudcannon.com/) — коммерческая платформа для хостинга и статических и гибридных сайтов. Он может соответствовать агентствам или командам, которые хотят управлять визуальным редактированием.

### Нагрузка CMS

[Payload CMS](https://payloadcms.com/) — бесконечная CMS с бэкэндом базы данных. Это не Git файл CMS, но он принадлежит в этом списке, когда "статический сайт" фактически нуждается в динамических моделях контента, Возможности API или приложения.

## Как выбрать

1. Начать с помощью модели контента: Если сообщения являются документами, то Markdown часто бывает достаточно. Если контент имеет сложные отношения, то оцените CMS, поддерживаемую базами данных.
2. Проверяйте правильность редактора: писатели обычно предпочитают редакторов документов; разработчики могут предпочитать schema-forms.
3. Защищает портативность: Предпочтительные инструменты, которые сохраняют контент как обычное Markdown/front дело в Git, когда долговременное дело переносимости.
4. Учетная запись для операций: Управляемый SaaS уменьшает процесс настройки, но добавляет зависимость от поставщиков; инструменты собственного хостинга обеспечивают контроль, но требуют обслуживания.

Моя рекомендация состоит в том, чтобы использовать Git основанный на CMS для блогов, документации, и маркетинговых сайтов, если у вас нет четкого требования к запросам данных во время выполнения работы или сложному реляционному контенту. Контраргумент действителен: после того, как ваша модель контента становится данными приложения, вынуждая ее в файлах Markdown создает свою собственную стоимость обслуживания.
