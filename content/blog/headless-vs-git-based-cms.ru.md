В заголовке CMS и Git на основе CMS описываются различные части контентной архитектуры. Бесголовной CMS отделяет управление контентом от презентации и обычно доставляет контент через API. CMS на основе Git хранит содержимое в виде файлов в Git репозитории и обычно публикуется через сборочный конвейер.

## Сравнение архитектуры

| Область           | Без заголовков CMS                                      | Git основанный на CMS                    |
| :---------------- | :------------------------------------------------------ | :--------------------------------------- |
| Основной вопрос   | Как контент доставлен?                                  | Где хранится контент?                    |
| Хранилище         | База данных или управляемое хранилище контента          | Файлы в Git-репозитории                  |
| Доставка          | API по запросу/времени сборки                           | Статическая сборка, обычно из CI/CD      |
| Изменить задержку | Часто сразу после публикации                            | После сборки и развертывания             |
| Versioning        | Ревизии платформы/рабочие процессы                      | Нативная Git история                     |
| Лучший подбор     | Многоканальные приложения, структурированное содержимое | Блоги, документация, маркетинговые сайты |

## Когда без заголовков CMS помещается

Бесголовной CMS является хорошим дополнением, когда один и тот же контент должен содержать несколько фронтендов, таких как веб-сайт, мобильное приложение и внутренний инструмент. Она также подходит в тех случаях, когда контент имеет сложные отношения, нуждается в обновлении в реальном времени или требует грандиозных редакционных разрешений.

Сделка осуществляется на оперативном уровне. Вы управляете контент-сервисом, доступом к API, изменениями схемы и интеграцией интерфейса.

## Когда приспосабливается CMS на Git

Когда содержание ориентировано на документооборот, а основной целью его доставки является создание веб-сайта. Markdown файлы в Git портативные, проверяемые и просты в версии. Издательская модель хорошо работает со статическими генераторами сайтов и CDN хостингом.

Отказ от сборки - задержка сборки и ограниченный запрос времени выполнения. Если вам нужна персонализация по запросу или сложные реляционные запросы, статический рабочий процесс на основе Git, может быть ограничивающим.

## Гибридные подходы

Некоторые команды используют и то и другое: CMS основанный на Git для документации или маркетингового контента, и бесконечный CMS с управляемым API для данных приложений. Полезное решение - не какая категория лучше в целом, а где каждый тип контента должен жить и как он должен быть доставлен.
