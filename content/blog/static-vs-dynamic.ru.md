Статические сайты служат готовыми файлами с CDN; динамические сайты генерируют ответы в момент запроса с использованием кода приложения и часто базы данных. Для блогов, документации, маркетинговых страниц, и большинство публикаций сайтов, статическая доставка, как правило, проще и дешевле, чтобы работать. Динамическая доставка лучше подходит, когда каждый запрос зависит от состояния пользователя или часто изменяет данные.

## Запрос сравнения потоков

| Шаг                     | Динамический сайт                                          | Статический сайт                                                           |
| :---------------------- | :--------------------------------------------------------- | :------------------------------------------------------------------------- |
| Время сборки            | Шаблоны и код развернуты во время выполнения               | Генератор сборки HTML/CSS/JS файлов                                        |
| Время запроса           | Приложение может запрашивать базу данных и отображать HTML | CDN служит предварительно собранным файлом                                 |
| Персонализация          | Нативная опция на стороне сервера                          | Обычно обрабатывается с клиентской стороной JS или edge/serverless функций |
| Неисправная поверхность | Приложение рабочего времени, базы данных, кэша, плагинов   | Создание трубопровода, CDN, интеграции на стороне клиента                  |

Динамический запрос страницы может включать маршрутизацию, запросы к базе данных, рендеринг шаблонов и логику кэширования. Запрос на статическую страницу обычно возвращает существующий файл из хранилища краев. Разница влияет на задержки, стоимость и оперативную сложность.

## Сделки для оценки

### Безопасность

Динамические сайты открывают время выполнения приложения, админ-интерфейсы и часто базы данных. Это создает возможности для внесения изменений и контроля за их выполнением. Статические сайты уменьшают поверхность взлома во время выполнения атаки, но им по-прежнему нужен безопасный доступ к Git, управление секретами CI/CD и обновление зависимостей в трубопроводе сборки.

### Производительность и стоимость

Статические файлы легко кэшировать на крае, что может сделать доставку быстрой и предсказуемой для сайтов содержимого. Динамические сайты также могут быть быстрыми с хорошим кэшированием, но они требуют большей настройки инфраструктуры.

### Рабочий процесс контента

Статические сайты исторически требовали работы разработчика для публикации. Git based CMS tools reduce that barrier by giving editors a browser interface while keeping content in Git. Динамические платформы CMS часто обеспечивают зрелые редакционные потоки из коробки, особенно для сложных разрешений и структурированного контента.

## Когда выбрать каждую модель

Выберите статический сайт когда:

- Содержание в основном одинаково для каждого посетителя.
- Вы хотите переносимые Markdown файлы в Git.
- Вы можете принимать публикацию в процессе сборки вместо мгновенных обновлений.
- Вы хотите низкий операционный накладной для сайта, сфокусированного на контенте.

Выберите динамический сайт когда:

- Пользователи регистрируются и просматриваются персонализированные данные.
- Контент или состояние постоянно меняются.
- Вам нужны сложные реляционные запросы по времени запроса.
- Поведение приложения - это продукт, а не просто издательский уровень.

Гибридный подход является обычным: статические страницы для содержимого, плюс функции безсерверного или API для форм, поиска, комментариев или аутентифицированных функций. For implementation details, see [What Is a Git based CMS?](/blog/Git based-cms-explained/) and [Static Sites and Carbon Emissions](/blog/greener-web-static-sites/).
