语音口述可以通过将语音注释转换成您CMS中可编辑的文本来加快起草。在Markdown Workflow 中，应将记录作为第一稿处理：对迅速收集想法有用， 但仍然需要编辑准确性、结构和语音。

## 如何配合博客工作流

实用的工作流程将捕获与编辑分开：

1. 记录粗略的想法：在不担心格式问题的情况下发表主要观点。
2. 抄录在草案中：在光标处或在草案中插入记录誊本。
3. 编辑结构：在捕获意见后添加标题、列表、链接和代码块。
4. 验证细节：在发布前检查名称、数字、产品条款和报价。

| 阶段 | 福利                 | 风险               |
| :- | :----------------- | :--------------- |
| 词典 | 更快的想法抓取            | 斜体或重复的短语         |
| 翻译 | 将语音转换为可编辑文本        | 首页、名称和技术术语可能错误   |
| 编辑 | 将文字转化为可公开内容        | 跳过审核可能会发布错误      |
| 发布 | 提交最终Markdown 到 Git | 敏感的音频/数据处理取决于提供商 |

## 准确性和隐私检查

语音和文字质量取决于麦克风质量、背景噪音、扬声清晰度和字幕模型。您应该查看每个记录，特别是技术术语、缩略语和数字。

在团队工作流程中使用口述之前，确认音频发送在哪里，保留了多长时间，是否用于模型培训。除非您的政策和提供者条款明确允许，否则不要规定秘密、凭据或私人客户信息。

## 当语音起草有用时

词句对初稿、会议说明、概要和粗略解释非常有用。它对精确的代码、表格或格式严密的内容的用处较小，直接打字的速度通常较快。折衷是捕获时间与编辑过程中的清理时间。
