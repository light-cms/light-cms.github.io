_Content as code_ 是用与软件工程师用于源代码相同的学科处理书面材料的做法：将文档作为纯文本文件存储在Git 存储库， 审查合并请求中的订正，使用自动CI 管道核实准确性，并在合并时部署静态输出。

这种做法常常被称为“作为代码的文件”，这是一个源自技术文献组的术语。

争辩的回报率比标签所显示的要小：内容作为代码使得更改可以审查和错误可以逆转。可携带性和备份来自同一架构，当内容需要相关查询或实时更新时，该方法就停止支付。

披露：LightCMS 维护者发布此日记，LightCMS 是以下链接的编辑器。

核心前提是直截了当的：生活在数据库支持的仪表板中的内容比Markdown 文件目录更难移动。

## 三个内容基础作为代码

为了有效地将内容作为守则，出版物承诺三项基本原则：

1. 原文作为Canonical Format: 内容存储在标准Markdown (`.md`或`.mdx`)中, 与 YAML 前缀。没有专有数据库架构、二进制文档蓝图或平台特定数据格式。任何计算机上的文本编辑器都可以打开和编辑您写过的每个单词。
2. Git 作为唯一的真理源：Git 存储库取代共享驱动器和wiki 作为土地编辑地。如果编辑被提交到仓库，它就存在；如果它没有被提交，它就不存在。完整的部落带有整个发布历史，这就是为什么任何开发人员结帐都可以作为备份。
3. 自动CI/CD 验证：内容被处理为编译代码。拉取请求触发连续集成运行器，检查破损的超链接，验证前方图案，运行拼写检查器，并在更改到达生产之前生成实时预览部署。

## 作者和编辑者免费继承什么

当内容生活在Git中，团队继承传统上需要昂贵的企业CMS插件或云端第三方添加的能力：

### Legiable, belle-line Revision Diffs

在传统数据库驱动的CMS中，要发现谁修改了句子或何时更新了免责声明，就需要通过不透明的数据库修订表进行核对。

使用 Git，差异是可读的纯文本。运行 `git log -p filename.md` 或打开 GitHub 上的提交突出显示了与作者姓名、时间戳和解释一起添加或删除的确切单词。

### 以编辑协作方式拉取请求

在许多组织中，编辑审查是共享文件链接、相互矛盾的建议和附件中的电子邮件线索中的混乱现象。

作为代码的内容将复习合并为合并请求。编辑们对具体句子留下一线评论意见，提出修改建议，辩论结构，并明确批准最后草案。将合并请求到主分支自动将文章部署到制作中。

### 独立，外科回滚。

如果在已发布的帖子中发现重大错误，回滚将是一个提交。恢复数据库备份通常也会回滚自备份后发布的所有内容。通过Git，您可以在单个文件上还原单次提交，然后将站点的其余部分留下来。

### 永久可移植性和灾后恢复

专有内容管理平台关闭、改变定价等级或获取，每个事件都将迁移到您的日历。

在 Git 仓库中的 Markdown 文件目录只需要一个文本编辑器来读。这并不能使该站点独立于所有东西：仓库主机，静态站点生成器。 而且部署管道仍然依赖于他们自己的迁移费用。什么是退出，因为内容移动时没有导出工具。

## 可能烦人的部分

像代码一样处理内容运行良好，但它不是免费的：

- 对于非技术作者来说，Git是粗略的。大多数人不想学习分支，合并冲突，或者只是为了发布一个帖子而本地开发程序。这就是为什么像 [LightCMS](/getting-started/)这样的视觉编辑器会有所帮助，因为它隐藏着Git机器。
- 大型媒体文件不属于Git。图片、视频和 PDF 可以快速博客。保存大文件并从Markdown引用它们通常是更好的。
- Markdown不是一个数据库。如果您需要关联内容、复杂查询或实时库存，数据库支持的 CMS 是更好的。

## 典型的内容为编程堆栈。

一个干净的现代内容代码架构看起来就像这样：

```text
my-publication/
/ id：--content/
circum. - - blog/
catximum - - 2026-10-16-shipping-notes. d
codifium - - 2026-11-04-content-as code。 d
codesin- - docs/
codes/ - quickstart. d
id. - --.github/
codectic - - workflows/
codectic - - deprive. ml # CI/CD validation & configuration
--astro. onfig.mjs # 静态站点生成器配置
```

1. 作者: 直观文章草稿 [LightCMS](https://www.lightcms.me)。
2. CMS将Markdown 和 YAML 前缀提交给一个功能分支；站点的设置是 LightCMS。
3. CI 管道运行着窗户，对照Zod方案检查前线，并建立了预览部署。
4. 编辑器审查在 GitHub 上的拉取请求，并点击"合并"。
5. 静态站点生成器编译文件，边缘CDN为全球更新服务。
