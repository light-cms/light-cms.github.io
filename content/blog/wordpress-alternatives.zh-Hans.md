当你想要较低的维护、较小的运行时攻击表面时，WordPress 备选办法是有道理的。 或者发布不依赖数据库支持应用程序的工作流。正确的重置取决于您是否需要一个内容网站、一个成员发布或者一个完整的应用程序。

## 为什么团队超越WordPress

WordPress 是灵活的，但其共同架构包括应用程序运行时间、数据库、插件、主题和需要持续维护的管理表面。

评价替代品的共同原因包括：

- 维护管理员：核心、插件、主题和 PHP 更新。
- 安全表面：公共管理端点和插件脆弱性。
- 性能工作：缓存、数据库调节和插件审计。
- 可携带性问题：内容和表述可以紧密结合起来。

## 按建筑结构分列的替代办法

| 选项类型                | 示例：                                  | 适合度好           | 折叠式...         |
| :------------------ | :----------------------------------- | :------------- | :------------- |
| 基于 Git 的 CMS + 静态站点 | LightCMS，Decap CMS，Pages CMS，TinaCMS | 博客、文档、营销网站     | 构建步骤；限定运行时动态行为 |
| 托管发布平台              | 幽灵：                                  | 新闻、成员资格、编辑发布   | 平台/数据库依赖关系和价格  |
| 传统企业CMS             | 迪帕尔                                  | 由发展团队组成的复杂组织站点 | 较高的安装和维护费用     |
| 无头CMS               | Contental, Sanity, Strapi            | 结构化多通道内容       | API/基础设施复杂度    |

## 选择 WordPress 选项

当你的站点主要是内容并且你想要版本控制中的 Markdown文件时，选择基于 Git 的静态工作流。当您需要会员、复杂的权限、实时个性化或应用程序功能时，选择一个数据库支持的平台。

我的判断是，基于静态Git的出版对于大多数博客和文件网站来说是一个更好的默认，因为它减少了运行时的复杂性。反参数是真实的：WordPress的插件生态系统和熟悉的管理体验对于需要动态功能的团队来说可以更快。
