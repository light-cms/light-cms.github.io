Статические сайты могут уменьшить энергопотребление, необходимое для обслуживания веб-страниц, перемещая работу с каждого запроса на построение времени и обработку кэшированных файлов с CDN. Они не являются автоматически низкими углеродами, а для контент-сайтов, которые часто избегают ненужных вычислений на стороне сервера.

## Почему статическая доставка может потреблять меньше энергии

Динамические веб-сайты обычно выполняют код приложения, запрашивают базу данных и генерируют HTML для каждого запроса.

Статические сайты генерируют HTML во время сборки и повторно обрабатывают результирующие файлы.

| **Фактор**            | **Путь динамического запроса**                              | **Статический кэшированный путь**                                           |
| :-------------------- | :---------------------------------------------------------- | :-------------------------------------------------------------------------- |
| По запросу работа     | Логика приложения и запросы к базе данных могут выполняться | Файл может быть отправлен из кэша                                           |
| Всегда инфраструктура | Сервер и база данных приложений часто требуются             | Сборки запущены по требованию; хостинг может быть основан на файлах или CDN |
| Кэширование           | Возможно, но часто сложнее                                  | Натуральная пригодность для неизменяемых или статических активов            |
| Контроль нагрузки     | Зависит от приложения и клиента                             | Зависит от создания вывода и выбора активов                                 |

Фактическое воздействие зависит от трафика, скорости попадания в кэш, хостинга источников энергии, веса страницы и JavaScript.

## Как измерять воздействие углерода на вебсайт

Оценки полезны для направления, неточности бухгалтерского учета. Используйте несколько инструментов и отслеживайте изменения с течением времени.

- [Website Carbon Calculator](https://www.websitecarbon.com/) Оценки выбросов на страницу.
- [Ecograder](https://ecograder.com/) Обеспечивает ориентированную на устойчивость оценку и рекомендации.
- Показатели производительности браузера, такие как Крупнейший Контентный рисунок, общий размер передачи и затраты на исполнение JavaScript помогают определить технические драйверы веса страницы.

Практическая базовая линия – это измерение верхних целевых страниц, размер записи и показатели производительности ключевых страниц, а затем повторение после оптимизации.

## Практика, снижающая влияние страницы

1. Сервируйте статические файлы с CDN: кэшировать HTML, CSS, JS и изображения рядом с пользователями.
2. Сокращение JavaScript: доставьте только код клиентской стороны, необходимый для этой страницы.
3. Оптимизация медиа: Сжатие изображений, использование современных форматов, где это уместно, и правильное размер активов.
4. Установка заголовков кэша: длительное время жизни кэша уменьшает повторные переводы.
5. Выберите хостинг внимательно: источники энергии дата-центра влияют на след.
6. Держите контент долговечным: Plain Markdown в Git уменьшает пересборку и миграцию отходов со временем.

## Не забывайте о сделках

Статическая архитектура не является полной стратегией устойчивого развития. Статический сайт с большими изображениями, видео автовоспроизведения, тяжелыми сторонними скриптами или плохим кэшированием может иметь больший след, чем тщательно оптимизированный динамический сайт. Полезный вопрос - это не "статичный или динамический?", а "сколько работы и данных требуется просмотр каждой страницы?"
