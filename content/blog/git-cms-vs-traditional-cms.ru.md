Традиционная CMS хранит содержимое в базе данных и обычно отображает страницы через сервер приложений. CMS на основе Git хранит содержимое в виде файлов в репозитории Git и публикует его через сборочную сборку. Правильный выбор зависит от того, является ли ваш сайт в основном контентом или в первую очередь приложением.

## Различия на ядре

| Область                          | Традиционная CMS                                                    | Git основанный на CMS                              |
| :------------------------------- | :------------------------------------------------------------------ | :------------------------------------------------- |
| Хранилище содержимого            | База данных                                                         | Markdown/файлы в Git                               |
| Рунтайм                          | Сервер приложений, база данных, плагины/темы                        | Статические файлы, отправляемые с CDN после сборки |
| Редактирование рабочего процесса | Администратор пользовательского интерфейса записывает в базу данных | Редактор создает коммиты/PRs в репозиторий         |
| Versioning                       | Редакции/плагины для конкретных CMS                                 | История Git, рассеивает, ветки, pull запросы       |
| Портабельность                   | Экспорт/миграция зависит от платформы                               | Файлы переносятся между генераторами и узлами      |

## Безопасность и оперативный уровень

Традиционные CMS платформы могут быть безопасными при правильном обслуживании, но они обычно содержат админ-интерфейс, прикладную среду, базу данных и экосистему плагинов. Это создает работу по исправлению данных и мониторингу.

CMS основанный на Git уменьшает поверхность приложения во время выполнения, так как опубликованный сайт может быть статичными файлами. Хранилище, Git хост и сборка трубопровода по-прежнему нуждаются в защитных контролях, включая управление доступом, защиту ветви и секретную обработку.

## Владение и переносимость

С помощью Git контент живет как файлы в вашем репозитории. Вы можете переместиться в другой генератор сайтов, хост или редактор с меньшим количеством преобразований форматов, когда содержание является простым Markdown и фронт-вопрос.

В традиционном CMS переносимость зависит от инструментов экспорта, схем баз данных, плагинов и шорткодов. Миграция возможна, но она часто требует очистки.

## Расходные расходы и расходы на обслуживание

Традиционные установки CMS могут включать хостинг, управление базами данных, плагины, резервные копии и обеспечение безопасности. Статические сайты на основе Git могут уменьшить инфраструктуру рабочего времени, но они все еще нуждаются в CI/CD, минутах, управлении репозиторием и инструментах редактора.

## Выбор между Git основанным на CMS и традиционным CMS

Традиционная или основанная на базе данных CMS обычно является правильным вызовом, когда вам нужны вещи, такие как учетные записи пользователей, персонализированные приборные панели, частые записи рабочего времени, разрешения на поле, или поведение приложения, что тесно связано с содержимым.

Основанный на Git CMS имеет больше смысла, когда сайт в основном контент, и вы заботитесь о портативности, рецензируемых изменениях, статических поставках и простой хостинг.
