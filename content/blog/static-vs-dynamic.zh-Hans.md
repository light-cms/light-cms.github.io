静态站点服务于来自CDN的预制文件; 动态站点使用应用程序代码和常常是一个数据库在请求时生成响应。对于博客、文件、销售网页和大多数出版物网站，静态发送通常更简单，操作更便宜。当每个请求取决于用户状态或经常更改数据时，动态传送更加合适。

## 请求流比较

| 步骤    | 动态站点               | 静态站点                |
| :---- | :----------------- | :------------------ |
| 构建时间  | 部署到运行时的模板和代码       | 生成器构建HTML/CSS/JS文件  |
| 请求时间  | 应用可以查询数据库并渲染HTML   | CDN 服务预制文件          |
| 个性化   | 本地服务器端选项           | 通常用客户端JS或边缘/服务器函数处理 |
| 失败的表面 | 应用程序运行时间、数据库、缓存、插件 | 构建管道，CDN，客户端集成      |

动态页面请求可能涉及路由、数据库查询、模板渲染和缓存逻辑。静态页面请求通常从边缘存储返回现有文件。这种差异影响潜在性、费用和业务复杂性。

## 要评估的取值

### 安全

动态网站会暴露应用程序运行时间、管理界面和数据库。这就产生了修补和监测责任。静态场地减少了运行时攻击表面，但它们仍然需要Git安全存取、CI/CD保密管理以及建筑管道中的依赖性更新。

### 性能和费用

静态文件很容易在边缘缓存，这可以使发送速度快和可以预测内容站点。动态网站也可以快速缓存，但需要更多的基础设施调整。

### 内容工作流

静态站点历史上需要开发者发布工作流。基于 Git 的 CMS 工具可以减少该屏障，允许编辑器接口同时将内容保留在 Git 中。动态CMS平台往往提供来自框的成熟的编辑工作流程，特别是对于复杂的权限和结构化内容。

## 何时选择每个模型

选择静态站点时：

- 每个访客的内容大致相同。
- 你想要在 Git 中的便携式Markdown文件。
- 您可以接受生成时间发布而不是即时运行时间更新。
- 你想要一个以内容为中心的网站的低操作管理费。

选择动态站点时：

- 用户登录并查看个性化数据。
- 内容或状态不断更改。
- 您需要在请求时间进行复杂的关系查询。
- 应用程序行为是产品，而不仅仅是发布层。
