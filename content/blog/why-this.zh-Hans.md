我们正在构建 [LightCMS](https://lightcms.me)，因为发布到静态站点不应要求每个作者关注开发者的工作流程。您可以在浏览器编辑器中写入，而您的内容仍然以Markdown 文件存在Git。

## 静态发布工作流问题

静态场地发电机可以直接建造和部署一个场地。为一个人写入仍然可以意味着克隆一个仓库，编辑Markdown，管理前体，执行和等待CI/CD。

这是开发者熟悉的领域。对于作者和编辑人员，它可以以发布方式进行。

## 为什么基于 Git 的内容仍然很重要。

在Git中保留内容可以给你一些实用的东西：

- 您可以审查、比较或还原的更改历史。
- 您可以在生成器、主机和编辑器之间移动Markdown文件。
- 一个直接通向基于 Git 的构建和部署工作流的路径，许多静态站点已经被使用。
- 您自己的仓库中的内容副本，而不是专有的 CMS 数据库。

## LightCMS放弃的内容

LightCMS是围绕Git发布而不是实时应用功能建立的。这对博客、文件和营销站点都很有效。如果您需要个性化，内容之间的复杂关系或运行时的数据库查询，那么另一种CMS可能会更好地适应您。

您在一个视觉编辑器中写入，而Markdown文件和 Git 历史仍然是真理的来源。关于该产品的更多信息，请参阅[What is LightCMS?](/blog/what-is-lightcms/)。
