我多年来尝试过几十个CMS，大多数人感到有点不错。它们起作用，但往往错过人类撰写和管理出版物的经验。

我发现的一个愉快的开发者工作流程最接近的东西是VS代码中的“前台事务”。它使管理内容文件变得更容易，但屏障仍然存在：打开一个完整的代码编辑器，拉取远程Git分支。 解决格式冲突和调试本地工具是三段思考的大量摩擦。

书面应当是容易的部分。

---

## 要分享的Imperative

拥有您在网络上的发布空间有真正的值：

1. **如果你多年来学到了一些东西，分享它。**
2. **如果你构建了一些令人感兴趣的东西，请写下它。**
3. \*\*如果你解决了一个花了三天时间才能理解的棘手错误，请记录它。 \* 六个月后，有人会寻找这个准确的错误并找到你的解决方案。

每个人都应该得到互联网的小角落。发布文章和技术洞察力不应依赖于控制您的内容或锁定在算法墙后面的专有社交平台。

然而开始并不需要您成为高级DevOps 工程师或全堆栈网络开发者。

---

## 静态站点Paradox

静态网站是在网络上发布内容的最简单、最快和最持久的方式：

- **快速**：预渲染的 HTML 和 CSS 是从边缘的 CDN 在全球范围内提供的。
- **Secure**: 没有服务器端运行时间或易受伤害的数据库侦听器暴露于公众手中。
- **生态友好** ：每页视图最小计算间接费用和零数据库查询减少数字碳排放(工具如[网站碳](https://www.websitecarbon.com/) 测量差异)。

不缺少能量的静态站点生成器： [Astro](https://astro.build), [Hugo](https://gohugo.io), [Jekyll](https://jekyllrb.com)、 [SvelteKit](https://svelte.dev)和 [Eleventy](https://www.11ty.dev)。

**自相矛盾的是，运行一个静态站点很简单，管理它不是。**

您不应需要了解 Git 重置基础标志、Markdown终端、前台事物YAML schema 验证器或 GitHub 令牌范围来发布您的想法。要求非技术性作者或老练的开发者在午夜导航VS代码是太多摩擦。

## 绿色网页是静态网络

静态出版在能量上获胜。有活力的站点每次请求都会断电； 一个静态站点进行一次性工作，并在接近阅读器的缓存中以一小部分能量提供结果。永远没有数据库，没有每个视图的计算方法，没有运往访客电池的运行时间。

持久的内容也是可持续的内容：您自己的存储库中的普通Markdown文件几十年来仍然可以读取和重建。 平台关闭，WordPress安装正常。从数据库驱动的托管到静态结构的每一个博客都是其碳足迹的永久、可衡量的减少。

更多: [静态站点和 CO2: 构建绿色网站](/blog/greener-web-static-sites/)。

## CMS停留在您的道路上

[LightCMS](https://lightcms.me) 旨在使写作和发布简单，同时不牺牲现代开发者工具的好处：

- **Content Lives in Git**: 您的文章仍然是纯粹的 GitHub 仓库中的 Markdown。
- **自动CI/CD**：您现有的构建管道(GitHub Actions, Vercel, Cloudflare页面) 继续自动构建和部署您的网站。
- **Frictionless Writing**：作者在浏览器、 写作、 格式和点击发布中打开一个无干扰的视觉编辑器。

你获得基于 Git 的存储库的所有可审计性、回滚安全性和所有权，而作者则获得一个无干扰的环境来写入。

## TL;DR

撰写博客文章不应感觉像高风险工程任务。把你的想法变成文字应该是容易的一部分。
