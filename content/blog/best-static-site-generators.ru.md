Лучший статический генератор сайта зависит от того, что вам нужно оптимизировать: скорость сборки, опыт разработчика, возможность создания шаблона эргономики или долговременная гибкость. Астро, Hugo, Zola, Eleventy, SvelteKit и Jekyll могут производить статические сайты, но они делают разные торги.

## Быстрое сравнение

| Генератор | Runtime/toolchain | Сильная подставка                                       | Главный трейд-офф                                       |
| :-------- | :---------------- | :------------------------------------------------------ | :------------------------------------------------------ |
| Астроо    | Node.js           | Сайты с компонентными островами                         | Накладные запасы экосистем/инструментов JS              |
| Уго       | В бинарный файл   | Большие сайты с быстрыми сборками                       | Перейти к шаблону кривой обучения                       |
| Зола      | Двоичный Ржавый   | Простые, быстрые сайты со встроенными функциями         | Меньшая экосистема                                      |
| Лифт      | Node.js           | Гибкий, минимальный вывод HTML                          | Больше решений по настройке активов/инструментов        |
| SvelteKit | Node.js + Svelte  | Статические сайты, которые могут перерасти в приложения | Больше времени выполнения фреймворка чем чисто SSG      |
| Чекилль   | Руби              | Простые страницы в стиле GitHub                         | Старые инструменты и медленные сборки на больших сайтах |

## Астроо

[Astro](https://astro.build) — это хороший выбор для сайтов, ориентированных на контент, которые нуждаются в современной эргономике. Она отображает статический HTML по умолчанию и поддерживает интерактивные острова.

Используйте Astro для создания шаблонов на основе компонентов, поддержки TypeScript или выборочного взаимодействия. Избегайте этого, когда вы хотите однобинарный инструмент с минимальными зависимостями.

## Уго

[Hugo](https://gohugo.io) построен для быстрого и простого развертывания. Его однобинарная модель делает его привлекательным для больших сайтов документации и архивов содержимого.

Использовать Hugo когда время сборки и эксплуатационная простота являются основными ограничениями. Ожидается дополнительное время обучения шаблонов Go при создании пользовательских макетов.

## Зола

[Zola](https://www.getzola.org) предоставляет один двоичный файл со встроенными функциями, такими как обработка Sass, подсветка синтаксиса и инструмент поиска и индекса. Его шаблоны Tera знакомы разработчикам, которые использовали синтаксис стиля Jinja.

Используйте Zola когда вы хотите простоту в Hugo, с более приемлемыми шаблонами. Маленькие темы и экосистемы плагинов могут быть ограничениями.

## Лифт

[Eleventy](https://www.11ty.dev) — гибкий и простой HTML-код без использования клиентского фреймворка. Поддерживает несколько языков шаблонов и позволяет управлять трубопроводом сборки.

Используйте Eleventy когда вы хотите контролировать разметки и минимальные предположения фреймворка. Планируйте принятие дополнительных решений вокруг объединения активов и структуры проекта.

## SvelteKit

[SvelteKit](https://svelte.dev/docs/kit) может предварительно отобразить маршруты для статического развертывания при сохранении модели компонента Svelte.

Используйте SvelteKit, когда сайт начинает статичный, но может потребоваться аутентифицированные или высокоинтерактивные функции позже. Для чисто контент-сайтов, он может быть больше фреймворка, чем вам нужно.

## Чекилль

[Jekyll](https://jekyllrb.com) сохраняет актуальность для простых статических сайтов и старых рабочих потоков, особенно когда для совместимости с GitHub страницами.

Используйте Jekyll для совместимости с существующим сайтом Jekyll. Для новых проектов тщательно сравните его с Гуго, Зола, или Астро.

## Общее преимущество: Markdown в Git

Большинство статических генераторов сайтов в этом списке могут читать файлы Markdown с фронтальным вопросом из Git-репозитория. Это делает контент портативным и разделяет ваш CMS и хостинг. Основанный на Git CMS типа [LightCMS](/getting-started/) может редактировать содержимое, пока ваш генератор обрабатывает сборки.

Если вы выбираете генератор, прототип одного и того же маленького сайта в двух кандидатах. Измерьте время сборки шаблона, оцените эргономику и проверите, как подходит ваша модель контента перед принятием.
